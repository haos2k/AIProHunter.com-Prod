OpenAlice自動化とHeartbeat：寝ている間もAIに市場を監視させる

2026年4月15日·13 min read

OpenAliceを使い始めたばかりのころ、こんな使い方をしているでしょう：何かを知りたいときに聞きに行く。答えてもらい、考え、たまにポジションの分析をしてもらう。

それは便利です——でも問題があります。自分から聞くことを忘れないようにしなければならない。

市場は待ってくれません。会議中にチャンスが現れます。寝ている間にFRBが声明を出します。食事中にNVDAが重要なレジスタンスラインを突破します。24時間市場を監視することはできませんが、本当に重要な瞬間を逃したくもありません。

それがまさにOpenAliceの自動化レイヤーが解決するために作られたことです。

イベントログ：すべての自動化のコア

CronとHeartbeatに入る前に、一つの基礎的な設計を理解する必要があります——追記専用のイベントログ。

OpenAliceのすべてのシステムアクティビティはこのログを通じて流れます：取引・AIメッセージ・スケジュールトリガー・Heartbeat結果——すべてが型付きイベントとして、リアルタイムサブスクリプションをサポートして流れ込みます。

この設計により自動化がクリーンになります：各機能はこのイベントバスの「リスナー」であり、自分のイベントタイプが入ってきたときに対応する動作をトリガーします。異なる機能は互いについて何も知る必要がありません——自分が関心を持つイベントをただ待つだけです。

これを理解すれば、Cron・Heartbeat・Webhookのロジックが明確になります——それらはすべて特定の条件下でイベントをログにプッシュし、AIがそのイベントを読んで行動するという仕組みです。

Cronスケジューリング：タイマーでAIタスクをトリガー

Cronにより時間ルールを定義し、指定した時刻に自動的にAIタスクをトリガーできます。

3つのフォーマットをサポート：

  • Cron式 — 精密な時間制御のための標準cron構文
  • インターバル — X分/時間ごとに実行
  • ワンタイムタイムスタンプ — 特定の瞬間に一度だけトリガー

実践的なユースケース：

# 毎朝9時に寄り付き前分析
毎日午前9時に、今日の寄り付き前の市場概況を教えて

# 週次ポートフォリオレビューリマインダー
毎週月曜の8時30分に、週次ポートフォリオ健全性レポートを生成して

# FRB決定日リマインダー
FRBが金利決定を発表する1時間前に知らせて

Cronトリガーが発火すると、OpenAliceはイベントをログに送ります。AIがそれを読んで対応するリサーチや分析タスクを実行し、結果を設定したチャンネル（Web UIまたはTelegram）に送ります。

Heartbeat：能動的な市場番人

Cronは「タイマーベースのトリガー」——市場がどうなっていようと、スケジュールした時刻に実行されます。

Heartbeatは違います——市場が実際にどうなっているかに基づいて、割り込みをかけるかどうかを判断します。

Heartbeatは定期的に市場状況をレビューする特別なCronジョブですが、「本当に注目すべき」ことが起きているときだけ能動的に通知します。「本当に注目すべき」とは何か——それはあなたが定義します。

Heartbeatのワークフロー：

定期トリガー（設定した頻度、例：30分ごと）
→ AIが市場状況をレビュー
→ 設定した条件に何か一致するものがある？
→ あり → 通知（Web UI / Telegram）
→ なし → 沈黙を保つ、割り込まない

ここで重要な設計の詳細があります：Heartbeatはアクティブなトレーディングセッションをフィルタリングします。特定の市場時間帯のみモニタリングし、市場が閉じているときは沈黙するよう設定できます——そうしないと深夜3時に「特に注目すべきことはありません」という通知が来てしまいます。

Heartbeatに設定するのに適した条件とは？

  • 特定の銘柄が直近の高値を突破するか、サポートを割り込む
  • テクニカルインジケーターが買われすぎ/売られすぎ水準に達する
  • マクロ指標（イールドカーブ・VIX）が閾値を超える
  • ポジションが注意を要する一定の比率だけドローダウンする
  • 財務ニュースに特定のキーワードが出現する（「FRB」「決算ミス」「地政学的」）

Heartbeatが解決するのは「あなたの代わりに決断すること」ではなく、「適切なタイミングで決断の場に連れていくこと」です。

Webhook：外部トリガーの統合

Webhookにより外部システムがOpenAliceにイベントをプッシュできます——これは計画中の機能ですが、設計コンセプトは今理解する価値があります。

ユースケースには：

  • TradingViewの戦略がシグナルを発し、WebhookでOpenAliceに通知する
  • APIサービスが特定のデータを返し、OpenAliceにイベントをプッシュする
  • 別のAIエージェントが分析を終え、OpenAliceをトリガーして取引を執行させる

この方向性は、OpenAliceを単独ツールとしてだけでなく、より大きなAIワークフローに接続できるノードとして位置づけます。

Telegram：モバイル取引レビューパネル

自動通知が役立つには、受信側が便利である必要があります——それがTelegram統合が存在する理由です。

OpenAliceにはTelegramボットがあり、以下ができます：

  • 能動的なHeartbeat通知を受け取る
  • Cronタスクの結果を受け取る
  • ポジション状況を確認する
  • AIがステージした注文をレビューしてプッシュ執行するかどうか決める

Telegramの取引レビューパネルは特に興味深い：AIがバックグラウンドで分析し、注文をステージし、コミットメッセージを添付——そしてTelegramメッセージを送ります。ちらっと見て、「執行を確認」か「無視」をタップします。

それだけです。ノートパソコンを開く必要も、証券会社のインターフェースにログインする必要もありません——スマートフォンでAIの推奨をレビューして執行させるかどうかを決める。

良い自動化ワークフローの設計

これらの機能を組み合わせると、本当に役立つワークフローを構築できます：

寄り付き前の準備（Cron）
毎日寄り付きの30分前に分析を自動実行：主要指数先物・前夜の米国市場の動き・今日の重要イベント（決算・FRB講演・重要指標）。結果はTelegramへ——通勤中に読み、デスクに着く前に方向感を持つ。

市場モニタリング（Heartbeat）
30分ごとに保有銘柄をレビューするHeartbeatを設定——異常があるときだけ通知する。通常の市場変動は注意が不要ですが、NVDAが1日で5%突然下落したり、VIXが30を突破したりすれば、すぐにアラートが来ます。

決断・執行（Trading-as-Git）
Heartbeatが通知をトリガーした後、AIはすでに潜在的な対応注文（例：ポジションの追加や削減）をステージしています。Telegramで説明をレビューしてプッシュするかどうかを決める。

この3つが連動することで、画面をずっと見ていた人と同じ市場反応速度が得られます——実際には画面をずっと見ることなく。

自動化の境界線

はっきり言っておく価値があることがあります：自動化を増やすほど、ガードパイプラインの重要性が増します。

AIが能動的にモニタリングし、自動的に執行するほど、ガードパイプラインに安全ガードレールを設定する必要があります——最大ポジションサイズ、注文あたりの上限、24時間の最大取引回数、自動執行にホワイトリスト化する銘柄。

OpenAliceの設計は段階的に自動化権限を拡大することを推奨します：まず通知のみモードでしばらく動かし、AIの判断が自分の嗜好と一致することを確認し、それから選択的に執行権限を開放する。最初から完全自動に設定しないでください——まだAIがどう考えるかを理解しているところです。

これはOpenAliceを信頼できないと言っているのではありません——自動化されたシステムは信頼される前に観察される必要があると言っているのです。

シリーズの終わりに

5本の記事を通じて、OpenAliceの全体像が明確になったはずです：

アーキテクチャ → 4つのレイヤー（トレーディング・リサーチ・自動化・インターフェース）、それぞれ明確な役割
環境構築 → Node 22 + pnpm 10 + Claude Code、5分の作業
トレーディング設計 → Trading-as-Git：ステージ・メッセージ付きコミット・プッシュ
リサーチツール → OpenBBエンジン・テクニカルインジケーター・ファンダメンタルズ・ニュースモニタリング
自動化 → Cronタイマー + Heartbeat条件トリガー + Telegramモバイルレビュー

ここからは、実際のワークフローに組み込んでいくことです——本当に気になる質問を聞き、実際に必要なHeartbeat条件を設定し、実際に保有しているポジションの分析に使う。

実際に使うことほど、理解を深める方法はありません。
