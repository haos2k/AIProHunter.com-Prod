カスタムコマンド：CMUXにワークフローを覚えさせる

2026年3月29日·5 min read

仕事を始めるたびに毎回同じことをしていないだろうか：npm run devを実行するペインを開き、プレビューブラウザを開くために切り替え、手元に置いておく別のシェルを開く？毎日3分が消えていく。

CMUXカスタムコマンドはまさにこれを解決するために作られた。cmux.jsonに固定の作業環境を定義し、1つのコマンドでworkspaceレイアウト全体を復元する。

cmux.jsonの場所

プロジェクトのルートディレクトリにcmux.jsonを作成する。CMUXが自動的に読み込み、内部で定義されたコマンドを利用可能なコマンドリストに追加する。

2つのコマンドタイプ

Workspaceコマンド：CMUXを開き、事前定義されたレイアウトでworkspaceを作成する — ターミナル、ブラウザ、分割設定が全て事前に指定される。「1日の開始」シナリオに最適。

シンプルコマンド：workspaceを作成せずにシェルコマンドを実行する。「テストを実行」や「環境を初期化」のような1回限りの操作に適している。

Workspaceコマンド：開発環境を定義する

設定の解説：

  • name / description：コマンドリストに表示されるラベルと説明
  • keywords：検索に使用 — キーワードを入力してこのコマンドを見つける
  • restart：workspaceが既に存在する場合、"confirm"は再起動するか確認する；"ignore"はスキップする
  • workspace.cwd：このworkspaceのデフォルト作業ディレクトリ
  • workspace.color：サイドバーでのこのworkspaceの識別色
  • layout：完全なレイアウト構造を定義する

レイアウトの論理：directionは分割方向（"horizontal"で左右、"vertical"で上下）、splitは分割比率（0.5は均等二分）、childrenにペインが含まれる。

この例が作るもの：左半分にNext.js、右上にブラウザプレビュー、右下にバックアップシェル。

いくつかの設計原則

キーワードを慎重に考える：コマンドが多くなったとき、keywordsが素早く見つける唯一の方法になる。["start", "dev", "run"]のような自然に入力するであろう動詞を含める。

cwdには相対パスを使う：./webは/Users/yourname/projects/app/webより良い — 設定を変更せずに異なるマシンで動作する。

カラーでカテゴリ分けする：異なるworkspaceタイプに異なる色を付ける — 開発は青、テストはオレンジ、監視はグレー。サイドバーを一目見るだけで全てがわかる。
