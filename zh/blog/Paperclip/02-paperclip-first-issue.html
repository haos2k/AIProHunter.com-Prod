Paperclip 第一張工單怎麼寫？用小店貼文實測一份可驗收範本

2026 年 11 月 27 日·10 min read

「幫店家寫三則貼文」是一個方向，還不是一張好工單。店家沒有提供價格、優惠、新品名稱或店址時，AI 很可能自己補齊細節；你若只檢查文句順不順，就可能把錯誤資訊交給客戶。

我在 Paperclip 建立了教學用的「青木咖啡」工單。品牌與委託是虛構的，下面的畫面、agent 執行與退稿紀錄則是本機實測。這篇拆開那張工單，讓你可以換成自己的工作來用。

手機閱讀時可點開操作截圖，查看原尺寸。

工單先寫四件事

Paperclip 的 Task／Issue 是一件工作的容器，有標題、描述、指派對象、狀態等欄位；官方 Issue 指南解釋了如何追蹤工作。但欄位本身不會替你定義品質。你要先寫好以下四件事：

要寫的項目 本次例子 少了會怎樣
已知資料 店名、手沖咖啡、每日現做司康、營業時間 AI 可能自行補產品細節
禁止推測 價格、折扣、產地、獎項、新品 看似完整的稿可能不能發
交付物 三則繁體中文貼文，每則 80–120 字 不知道該交幾份、長到哪裡
驗收條件 每則附一個具體待確認事項，不對外發布 「寫完」可能被誤當「可上架」

你可以把這段範本貼進 New task，替換品牌資料：

  • **標題：**替〔店名〕寫下週三則社群貼文草稿
  • 已確認資料：〔列出客戶提供且允許公開的資料〕
  • **不能自行補寫：**價格、優惠、產地、獎項、客戶評價，以及任何尚未確認的新品資訊。
  • **交付：**三則繁體中文草稿，每則 80–120 字，主題各不相同；每則後寫出具體「上架前需核對」事項。
  • **完成條件：**正文符合字數、沒有未提供的事實、核對事項能交給店主回答。請留在工單，不要發到社群平台。

把客戶一句話改成可驗收的要求

客戶常說「幫我寫得有吸引力一點」，這句話可以保留為風格方向，卻不能單獨當驗收條件。你要往下問：要給誰看、在哪個平台刊登、有幾則、哪些事實可以寫、哪些資訊要再確認。以本例來說，「三則繁體中文、每則 80–120 字、主題不同」能檢查；「有吸引力」則需要客戶提供喜歡或不喜歡的範例，才有討論依據。

工單也應分開寫「正文」與「待確認事項」。正文是準備給讀者看的文字；待確認事項是交給店主回答的問題，不應混進貼文裡。若 agent 只輸出一個「待確認」標籤，你可以直接指出它沒有完成哪一項，而不用說「感覺不夠完整」。這正是本次 QA 退回三則改稿的依據。

為什麼我把「新品」從任務中拿掉？

第一張實測工單要求一則「新品介紹」，但我給 agent 的資料裡沒有任何新品。它交出了一篇像新品預告的草稿，同時提醒須確認是否真的有新品。這個提醒是對的，可是這則文案仍不能交付作為可發布內容。

我沒有用一句「寫好一點」退稿，而是讓資料查核 agent 接下一張工單：只整理客戶真正提供的資料，把其他內容列為待確認。查核結果清楚指出，店名、產品類型和營業時間可用；新品、價格、折扣、產地與獎項不能自行補。Paperclip 的工單狀態讓研究和寫作能分別追蹤，誰提供的結論也能回查。

接著我把貼文主題改為手沖咖啡、週末來店、司康搭配。這三題都能用已知資料起稿。但改稿 agent 又犯了另一個錯：每則末尾只寫「上架前需核對」，沒有真正列出要問店主什麼。校對 agent 逐項查核，判定三則正文符合字數和禁語要求，仍全部退回補件。這就是驗收條件有用的地方：文案讀起來順，不代表已達交付標準。

退稿時只改一個明確缺口

假設你收到的文案語氣合適，只有第二則把「週末照常營業」寫成沒有例外的承諾。退稿可以寫：「保留第二則的主題與字數；刪除未經確認的週末營業保證；在文末列出要向店主核對的具體日期。」這樣編輯知道要動哪一則、保留什麼、何時算完成。若只回「再自然一點」，下一版可能改了所有句子，卻沒處理真正的風險。

本次實測的補件也是同一原則：三則正文已通過字數與禁語檢查，就只補三個具體核對問題。把通過的項目和退回的項目分開記，能讓後續驗收集中在變動處；但若新版本改動了正文，仍要重新檢查正文是否引入新的說法。

交稿前照這份清單驗收

你不必等到建立 QA agent 才能檢查工單。先把原始委託放在旁邊，逐則問：主題是否符合店主需求？正文是否在指定字數內？每個具體事實能否在委託或店主答覆中找到來源？是否出現價格、優惠、新品、獎項等沒有提供的資訊？「上架前需核對」是否寫出能讓店主回答的問題？最後確認稿件只留在工單，沒有被當成已核准的發文內容。

這份檢查會產生三種結果：通過、退回修改、等待客戶回答。三者不要混用。「等待回答」不是 agent 再寫一次就能解決；「退回修改」則要指出能修改的句子與規則。本站第一輪的新品問題屬於缺客戶資料，第二輪空白核對欄位屬於交付格式缺件。分清原因，下一步才不會叫錯人做錯事。

自己試一次，怎麼判斷工單寫得夠清楚？

建好工單後，先別急著指派。問自己三個問題：一、agent 能否只憑工單拿到必要資料？二、它若自行加了客戶沒說的資訊，我能否指出違反哪一條？三、它交回結果時，我能否逐項說出通過或退回的理由？如果任何一題答不出來，先補工單，通常比事後反覆改稿省心。

對接案者而言，這張工單也能變成客戶資料表：尚未確認的欄位先回問店家。你賣的不是「AI 三秒寫貼文」，而是一份有人把關、知道哪些內容能公開的交付物。是否能縮短實際工時，還要把你寫任務、驗收與改稿的時間一併記錄；本案例沒有人工對照組，不宣稱節省比例。
