Paperclip 安裝教學：從一行指令到第一家公司

2026 年 11 月 26 日·10 min read

想試 Paperclip，先別急著「雇十個 AI 員工」。你第一個要得到的結果很小：在自己的電腦打開 Paperclip 網頁，建一家公司，知道下一步要接哪個模型。這篇只做到那裡，並把本站實測遇到的安裝問題攤開來說。

Paperclip 是自架軟體。你需要有一台能執行 Node.js 的電腦、終端機，以及之後要供 agent 使用的 Codex 或 Claude 帳號／API 憑證。官方安裝指南目前要求 Node.js 24.11 以上。本站於 2026 年 11 月 25 日在 macOS arm64、Node.js 24.22.1 上實測，Paperclip 健康檢查回報版本 2026.1117.0。

若看到 v24.11.0 或更新版本，可繼續。若顯示找不到指令，先依 Node.js 官方下載頁安裝。第一次用終端機不需要理解資料庫或伺服器原理；你只要知道下面的指令會把 Paperclip 裝在本機，預設網頁位址是 http://localhost:3100。

npx 會下載並執行套件；onboard 做初始設定；--yes 採用快速入門預設值。執行後先看終端機是否列出設定完成，再打開網址。不要把「終端機印出網址」誤當成 agent 已能做事：模型連線是後面的步驟。

第二步：在網頁輸入公司名稱

本站打開本機介面後，看到第一個問題是「What is the name of your organization?」。我們輸入「小店內容工作室」，用來管理青木咖啡的教學任務。這個名稱只是工作空間標籤，不需要成立法律上的公司。

手機閱讀時可點開操作截圖，查看原尺寸。

畫面下一步要求替第一名 agent 命名。你可以叫它「內容企劃」，讓往後的任務分派比較好認；但光有名字還不會執行，還要連到 Codex 或 Claude。Paperclip 的官方五分鐘路徑依序介紹建公司、雇第一名 agent、觀察它開始工作。

這次案例的正式公司和 agent 是透過本機 Paperclip API 建立，並使用本機已登入的 Codex CLI；上面兩張截圖是同一實測環境的初次設定畫面。若你打算完全使用網頁，照畫面接著選模型並完成登入即可；不要把本站的 API 設定過程當成每位新手都必須輸入的指令。

第一次進介面，先確認三件事

看到公司名稱與 agent 名稱後，先停下來檢查：網頁能否重新整理後正常打開、公司名稱是否出現在你預期的工作空間、agent 是否有可用的執行方式。前兩項只表示 Paperclip 介面與資料能正常顯示；第三項還要實際執行一張小工單才知道。把這三件事分開檢查，遇到錯時才不會把「模型登入失敗」誤當成「Paperclip 沒裝好」。

接著記下你的作業系統、Node 版本、Paperclip 版本和啟動方式。下次更新或排錯時，這四項能幫你比較「以前能跑、現在不能跑」究竟改了哪一段。若是要給客戶使用，也先確認資料存在哪裡、誰能存取，再放入真實委託；本站的第一輪練習只使用虛構資料。

本站為什麼沒有一次安裝成功？

我們先試了 Paperclip 的 test-drive，它會建立隔離的測試資料目錄。健康檢查的 12 項一度全過，啟動伺服器時卻卡在內建 PostgreSQL 初始化。也就是說，「doctor 全綠」仍不等於網頁已經能用。接著我們改以本機 Docker PostgreSQL 啟動同一套 Paperclip，/api/health 回報 status: ok，網頁才真的打開。

這不是每台電腦都會遇到的錯，也不表示你一開始就該裝 Docker。若你的 onboard 正常打開網頁，繼續即可。若像本站一樣卡在資料庫，先記下錯誤訊息、Paperclip 版本、作業系統與 Node 版本，再對照官方資料庫部署說明選擇內建或外部 PostgreSQL。初學者不要在不清楚資料位置時刪除現有資料目錄。

卡住時依畫面分段排查

若 node -v 就失敗，先處理 Node 安裝；若終端機能執行 onboard，但網址打不開，回去看啟動訊息與資料庫錯誤；若 Dashboard 可以看、agent 卻不能執行，才去查模型登入和 adapter 設定。每一步只改一個變數，再重新嘗試，較容易知道是哪個調整奏效。

本站遇到的是伺服器啟動階段的資料庫問題，改用外部 PostgreSQL 後才打開網頁。這個經驗不能推成所有人都要安裝 Docker，也不能用來解釋每種 agent 執行失敗。保留原始錯誤訊息，對照對應的官方文件，比照抄別人的排錯指令可靠。

準備好第一張工單的最低條件

公司建立成功後，先不要輸入真實客戶的整份資料。你可以用四行虛構資訊測試：店名、產品、營業時間、哪些資料不得自行推測。給第一名 agent 一張只需整理「已知／待確認」的小工單，觀察它能否被指派、是否開始執行、結果有沒有回到工單。如果這個短任務都無法完成，先解決連線或權限問題，再擴大到三則貼文。

這個檢查也能建立一條清楚的成功界線：Dashboard 打開，只代表介面可用；agent 出現在列表，只代表角色已建立；能在指定工單留下可核對的結果，才代表從輸入到交付的基本路徑跑通。本站後來仍遇到狀態沒有同步的情況，所以第一次成功後也要看工單狀態是否符合實際結果。

請把第一次成功的狀態記下來

第一次跑通後，建議替自己留一份簡短紀錄：執行的是哪個安裝指令、Node 與 Paperclip 版本、網頁位址、使用哪種模型登入，以及測試工單有沒有真正產生結果。之後若更新套件或換電腦，這份紀錄能幫你比較差異。特別是登入方式，可能決定成本顯示的口徑；不要只記「有連上 AI」，卻忘了是訂閱登入還是 API key。

若你要把同一套環境用於長期接案，也應在存入真實資料前確認資料備份與存取權限。本站這次用的是暫存的本機測試環境，沒有把虛構案例當成正式客戶系統來運作。先用小工單驗證操作，再決定是否要維護長期環境，比一次把所有客戶資料搬進去更容易發現設定問題。

成功畫面長什麼樣？

你最後要能看到公司 Dashboard，裡面有 Tasks、Agents、花費與審批入口。我們的畫面已經有案例工單，所以比剛建好的空白公司更滿；你的第一個 Dashboard 若沒有任務，屬正常情況。

這一步花掉的時間也要算進之後的效益評估。本站碰到資料庫問題，安裝明顯不是「五分鐘完成」；官方說的五分鐘入門，是安裝完成後建立公司和 agent 的路徑，不包含每種電腦可能遇到的排錯時間。
