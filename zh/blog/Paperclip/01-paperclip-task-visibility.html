Paperclip 是什麼？我用一家虛構小店跑出五張 AI 工單

2026 年 11 月 25 日·11 min read

一位接案者收到小店的委託：「下週幫我準備三則社群貼文。」他可以開一個聊天視窗，請 AI 一口氣寫完。但若店家只給了產品和營業時間，AI 很容易把「新品上市」「限時優惠」也寫進去。真正花時間的工作，往往是查核、退稿、確認誰還欠什麼資料。

我用 Paperclip 做了一次小型演練。案例中的「青木咖啡」是教學用虛構品牌；Paperclip 畫面、工單、agent 執行和審核紀錄則來自本站 2026 年 11 月 25 日的本機實測。這不是客戶訂單，也沒有產生收入。

手機閱讀時可點開操作截圖，查看原尺寸。

上圖是實際建立「小店內容工作室」後的 Dashboard。它把 agent 執行、待辦工單、花費與審批集中在同一處。這就是 Paperclip 的用途：替多個 AI agent 管工作流程。文章或程式仍由你接入的 Codex、Claude Code 等工具完成，Paperclip 負責交付、狀態、預算和留痕。官方定位也是把它放在 agent 上層的管理位置。

這次交給 Paperclip 的工作是什麼？

虛構店家只提供四項資料：店名青木咖啡、主打手沖咖啡、每日現做司康，以及週二至週日 10:00–18:00 的營業時間。我把「價格、折扣、產地、獎項、新品」列為沒有證據就不能寫的項目。最後共建立五張工單：初稿、資料查核、依查核結果改稿、內容校對，以及按校對意見補件。

第一輪初稿真的跑出了三則貼文，卻碰上兩個問題。第一，工單要求「新品介紹」，但委託沒有任何新品資料；agent 在稿末提醒須確認，這則仍不能直接用。第二，agent 無法從自己的執行環境連到本機 Paperclip API，雖然完成摘要出現在工單留言，工單狀態沒有跟著結束。這些細節說明：有人驗收，才知道任務是否真的完成。

後續的資料查核 agent 把資訊分成「已提供」與「待店主確認」；貼文編輯依此重寫，卻又把每則文末的「上架前需核對」留成空標籤。交給校對 agent 的工作，正是找出這種看似交付、其實還欠具體內容的地方。

如果不用工單，問題會在哪裡出現？

想像同一份委託只有一個聊天紀錄：第一輪生成三則貼文，第二輪補上營業時間，第三輪刪掉新品，第四輪請 AI 校對。過了兩天再打開，你可能記得「已經改過」，卻不確定校對看的是哪一版，也不確定店主是否回答過供應問題。真正難追的不是文字，而是每個決定的依據。

在這次案例，第一張工單保留了錯誤的「新品」要求，第二張記錄可用事實，第四張列出退回原因，第五張才是補件稿。你可以從結果往回追：某句話來自客戶原始資料、agent 的推測，還是後來的人工修改？若答案找不到，就先不要把那句話當作已核實資訊。Paperclip 的任務列表提供位置，資料是否可靠仍要靠人逐項核對。

一般人能得到什麼好處？

如果你是接案者，這套流程最實際的用途是把內容服務拆成可驗收的交付物：先收店家資料、再做研究與文案，最後保留人工核稿。你可以把「一週三則貼文與查核清單」設計成服務，但能否賺錢取決於有沒有客戶、報價與交付品質；Paperclip 本身不會替你帶來訂單。

省時間也需要實測。我們這次的改稿工單確實由 agent 完成，但沒有記錄同一任務由人手工完成的基準，因此不會宣稱「省了幾小時」。你能立刻拿走的，是一種減少反覆追問的做法：每張工單先寫清楚輸入、禁止推測的資料、產出格式、驗收條件。當結果有問題，能指向某一張工單退回。

費用方面，這次使用已登入的 Codex 訂閱。Paperclip 顯示已記錄的 API 支出為 USD 0，但這不代表訂閱免費，也不代表換成 API key 執行仍是零成本。預算與供應商帳單必須分開看。官方成本說明也列出訂閱費、已記錄用量和預算的不同口徑。

什麼工作值得先拿來試？

第一次使用，挑一件每週會重複、資料不敏感、做錯後容易退回的工作。例如把既有產品資料整理成三則草稿，交付後由你檢查。先別把「自動發布」列入試跑目標；這次案例也只做到草稿與審批紀錄。試跑時留下三種東西：原始委託、每張工單的完成條件、最後人工修改了什麼。這些紀錄比單看 AI 產出速度更能幫你判斷是否值得繼續。

若你的工作每次都只有一句短文、沒有資料查核或交接，建立公司與多名 agent 的準備成本可能高於收益。反過來說，若每週都要重複收資料、交稿和退稿，流程留下來之後才有機會減少來回確認。這是選試驗題目的方法，不是本站已測得的省時結論。

先把幾個名詞翻成日常工作

如果你還不熟悉這類工具，可以先用接案工作室來理解：公司是放同一批工作的空間，agent 是被指定職責的 AI 執行者，工單 是一件具體待辦，審批 是需要人拍板的決定，Skill 則是可重複使用的工作說明。這些名稱不代表它們擁有真人員工的判斷力，也不代表建好後就會自行知道客戶想要什麼。

以青木咖啡為例，「內容校對」agent 可以依工單檢查每則貼文是否有價格、優惠等未提供資訊；它不能代替店主確認週末是否臨時休息。你要把誰負責執行、誰能提供事實、誰能批准發佈分開。讀這個系列時，若某一步出錯，也可以用這幾個名詞定位：是原始資料不足、工單沒寫清楚、agent 執行失敗，還是最後的人沒有確認？

你需要先會寫程式嗎？

不一定。安裝後主要可在網頁操作，但第一次仍要準備 Node.js、終端機指令，以及 Codex 或 Claude 的登入／API 憑證。官方入門路徑也把安裝和模型連線列為前置工作。若你只要請 AI 改一句廣告文案，直接聊天更快；當你有多張互相依賴的任務，需要追蹤誰完成、誰退回、花了多少，Paperclip 才有發揮空間。

這個系列會從安裝開始，帶你看一張真實工單如何被執行、出錯、修正與審核。

10 篇系列怎麼讀

  1. **本篇：**Paperclip 的用途與案例全貌。
  2. 從安裝到第一家公司：準備環境與進入介面。
  3. 第一張工單怎麼寫：把需求寫成能驗收的任務。
  4. 雇用第一個 agent：選角色、接模型、看第一次執行。
  5. 把一週貼文拆成研究、寫作、校對：安排交接。
  6. 預算上限與真實花費：看懂帳面數字。
  7. 哪些事要人工批准：保住發佈決定權。
  8. 從零做出小店社群內容包：完整看成果與退稿。
  9. 用 Skill 重複每週流程：整理可重用的操作。
  10. Paperclip 值不值得用？：計算自己的投入與回報。
