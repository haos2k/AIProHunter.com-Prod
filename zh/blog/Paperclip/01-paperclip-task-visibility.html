Paperclip 把 AI agent 排成一家公司後，誰來替你盯進度？

2026 年 11 月 15 日·6 min read

Paperclip 是什麼？

Paperclip 是一套組織和管理多個 AI agent 的平台。你在裡面建立「公司」、設定目標，接入實際做事的 AI agent，再透過工單分派任務、查看進度、設定預算與保留人工審核。Paperclip 負責管理流程；產出內容或修改程式的仍是你接入的 agent 與模型。官方入門說明把它定位為代理上層的管理系統。

它怎麼把工作串起來？

先想像一個只有你和兩名 AI agent 的小團隊。Paperclip 裡的「公司」是這個團隊的工作空間，放目標、代理、任務和預算；每名 agent 有自己的角色與執行設定；issue（介面稱 Task）是一張交給特定 agent 的工單。agent 在執行時更新工單，完成後你再看結果是否能通過審核。核心概念文件也說明了 agent 的 heartbeat：它們按觸發條件醒來做一段工作，並非一直在背景運作。

如果你只想問模型一個問題，直接開聊天視窗就夠了。Paperclip 比較適合有多個代理、任務會互相交接，而且你需要追查「誰做了什麼、花了多少、現在卡在哪」的情況。這是依產品設計作出的使用判斷，並非本站實測的省時結論。

拿一篇工具介紹做例子

假設你要寫一篇 AI 工具介紹，找資料交給一個 agent，整理大綱交給另一個，自己負責最後查證。三份工作都在跑，最麻煩的往往不是「誰還沒做完」，而是哪一份結果正在等你看、哪一份已經被退回去重做。

先把交付物寫得夠窄：「整理 Paperclip 官方文件中的任務、預算與審核方式；每一點附原始網址；不寫實測心得。」研究 agent 只負責這張工單。下一張「把已核對的資料排成文章大綱」交給寫作 agent。最後的查證與發稿，留給人。

這裡最有用的是工單狀態與責任歸屬。當研究尚未交付，大綱任務就不該被當成已具備來源；當草稿寫完，發稿也不該自動等於核准。Paperclip 的 issue 文件可用來核對目前介面如何記錄指派與狀態。

查官方文件 三項功能及原始連結 編輯核對連結
寫文章大綱 不超過五段、每段有讀者問題 編輯檢查是否重複

跟著官方入門路徑看一次

這是依官方文件設計的操作演練，本文尚未連接模型執行；介面名稱與順序請以當天的五分鐘入門指南為準。

  1. 建立一個公司，目標只寫「完成一篇有來源的產品介紹」。先別把研究、寫作、社群發佈一次全開。
  2. 建立一名負責研究的 agent，確認它使用的 adapter 與模型設定。沒有模型憑證，可以先看組織與任務欄位，不要假裝它已執行。
  3. 建立上表第一張工單，貼入官方文件網址、交付格式和驗收條件，再指派給研究 agent。
  4. 從 dashboard 和 issue 頁面觀察：誰負責、目前狀態、是否有待審核事項。真的執行後，保留畫面及工單紀錄，才能評估追蹤是否比原本方便。

讀者真正能帶走的是一個判斷法：**若工作只有一個 agent、一個任務，額外的組織層可能比工作本身還重；若任務互相依賴，工單與審核的可見性才有價值。**這是由產品設計推得的適用情境，仍要用自己的工作量驗證。
