建立、切換、刪除 Worktree：CCManager 的核心操作

2026 年 5 月 21 日·4 min read

上一篇把 Git Worktree 的概念說清楚了。這篇進操作——從 CCManager 介面把 Worktree 建起來、跑 Agent、改完合回去。

不複雜，但流程要走對，不然後面想刪掉的時候會卡住。

建立新的 Worktree

從 CCManager 主選單選 New Worktree，會跳出對話框，填兩個東西：

  1. Branch 名稱：新 Worktree 要 checkout 的 branch，例如 feature/add-auth。如果這個 branch 不存在，CCManager 會自動建立。
  2. 目錄路徑（可選）：Worktree 要放在哪個目錄。不填的話，CCManager 會根據 branch 名稱自動產生路徑——通常是在 repo 旁邊同層的目錄。

填完確認，Worktree 就建好了，對應的 AI Agent 工作階段會自動開啟。

自動產生目錄路徑

每次手動填目錄路徑有點煩。你可以在設定裡開啟自動路徑產生：

Global Configuration → Configure Worktree → Auto-generate directory path

設定 pattern 的時候可以用 {branch} 這個 placeholder，CCManager 會把 branch 名稱填進去，然後自動做 filesystem 安全處理（斜線之類的字元會被替換）。

比如 pattern 設 ../worktrees/{branch}，建 feature/add-auth 的時候目錄就自動變成 ../worktrees/feature-add-auth。設好之後建 Worktree 快很多。

複製 Claude 工作階段資料

建新 Worktree 的時候，對話框會問你要不要把當前工作階段的 Claude 對話資料複製過去。

選「複製」的話，CCManager 會把 ~/.claude/projects/[原路徑] 底下的所有工作階段檔案複製到新 Worktree 對應的路徑。新 Worktree 裡的 Claude 就能延續之前的對話，不用重新介紹專案背景。

選「不複製」的話，新 Worktree 的 Claude 是全新的狀態。

哪種好？看情況：

  • 繼續同一個功能的延伸開發，或在同一個專案背景下做新任務——複製，省掉重新建立上下文的時間
  • 做完全不相關的新任務，或你不想讓 Agent 受之前對話影響——不複製，乾淨開始

預設行為可以在 Global Configuration → Configure Worktree → Copy Session Data 設定。

切換工作階段

從主選單看到所有 Worktree 的清單，每個旁邊都有狀態標示。選一個按 Enter 就切進去了。

從工作階段回到選單，按 Ctrl+E（或你自訂的快捷鍵）。

刪除 Worktree

任務做完要清理，從主選單找到那個 Worktree，選 Delete Worktree。CCManager 會把 Worktree 目錄移除，並清除對應的 Git Worktree 紀錄。

刪之前記得確認：

  • 改動有沒有 commit 或 push
  • 這個 branch 還需不需要

刪掉之後還原麻煩，小心一點。

合併回主線

CCManager 裡有 Merge Worktree 的選項，可以把 Worktree 的 branch 合進你指定的目標 branch（通常是 main 或 develop）。

合併完之後，Worktree 通常就可以刪了——任務結束，Worktree 的生命週期也結束。

Worktree 的建立、切換、刪除都跑過一遍了。
