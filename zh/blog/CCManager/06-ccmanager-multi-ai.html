不只 Claude Code：CCManager 支援哪些 AI 助手

2026 年 5 月 25 日·4 min read

CCManager 不是 Claude Code 專用工具——雖然預設跑的是 claude，但它支援的 AI coding 工具比你想的多。

如果你在不同專案用不同 AI，或是想在同一個 CCManager 裡混用，這篇說的就是怎麼做。

支援的 AI 助手清單

AI 助手 指令 安裝
Claude Code claude code.claude.com
Gemini CLI gemini github.com/google-gemini/gemini-cli
Codex CLI codex github.com/openai/codex
Cursor Agent cursor-agent cursor.com/cli
Copilot CLI copilot github.com/github/copilot-cli
Cline CLI cline github.com/cline/cline
OpenCode opencode opencode.ai
Kimi CLI kimi kimi-cli.com

每種工具都有對應的狀態偵測策略，讓 CCManager 能正確判斷這個 Agent 現在是 busy、waiting 還是 idle。這件事在背後自動發生，你通常不需要動它——除非你的工具行為很特殊。

切換預設工具

要換掉預設的 claude，去：

Global Configuration → Configure Command Presets

把 Command 改成你要用的工具指令，比如 gemini 或 opencode。儲存之後，新建的工作階段就會跑你指定的工具。

設定主要參數與備援參數

Configure Command Presets 裡除了指令，還有兩個參數設定：

Primary Arguments：主要的啟動參數，比如 --resume（讓 Claude Code 直接接上前一個對話）。

Fallback Arguments：如果主要參數跑起來失敗，自動退回這組參數試試看。最後的底線是不帶任何參數——CCManager 會一路 retry 到跑起來為止。

這個備援機制在遠端環境或設定比較複雜的 devcontainer 裡特別有用，不用手動處理啟動失敗的狀況。

Claude Code 的特殊設定：Teammate Mode

用 Claude Code 的話，CCManager 有一個自動行為值得知道：它會在啟動 claude 的時候自動加上 --teammate-mode in-process 這個參數。

這個 flag 是為了避免 Claude Code 的 agent teams 功能跟 CCManager 的 PTY 工作階段管理打架。

完全自動，不用你設定。 但如果你自己在 preset args 裡指定了 --teammate-mode，你的設定優先，CCManager 不會蓋掉它。

如果你用的是 Gemini、Codex 等其他工具，這個 flag 不會被加上去——只有 claude 指令才會觸發。
