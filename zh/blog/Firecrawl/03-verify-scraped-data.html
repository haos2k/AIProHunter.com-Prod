Firecrawl 抓到資料後怎麼驗證？以美術館開放時間做來源表

2026 年 11 月 26 日·8 min read

幫朋友做美術館參觀指南，最怕把「星期一休館」漏掉，或者把週六延長時段寫成每天都適用。Firecrawl 可以把網頁抓成文字，但參觀者真正需要的是當天可用的資訊。這篇用臺北市立美術館官方開放時間頁做一張來源表：你看完能把擷取文字與原頁逐項對照，並知道何時必須重查。

本站於 2026 年 11 月 26 日用 /v2/scrape 要求 Markdown，Firecrawl 回 HTTP 200、success: true、來源頁狀態 200，Markdown 長度 6,659 字元。頁面文字有週一休館、週二至週五與週日 09:30–17:30、週六 09:30–20:30。這是當日觀測，不是往後每週的營業保證；實測摘要已保存在本站系列紀錄。

先抓一次，再回原頁

請求格式與官方 Scrape 文件一致。若要重做，將官方網址送到 /v2/scrape，formats 設為 markdown；把 API 回應、抓取日期與原網址存成一組。資料要對外發布時，當天再用瀏覽器看一次官方頁，尤其注意臨時公告、假日與特殊展覽是否另有規定。

不要只判斷 success: true。它表示 API 完成一次擷取，沒有替你證明每個時段都完整，也沒有證明使用者造訪那天沒有臨時調整。把「欄位、擷取文字、原頁位置、最後查核日」放在同一列，審稿時才有地方追問。

要發布的欄位 2026-11-26 擷取所見 原頁核對與行動
週一 休館 回官方開放時間頁確認；節假日另查公告
週二至週五、週日 09:30–17:30 確認時段沒有被特展說明覆蓋
週六 09:30–20:30 獨立列出，避免套用平日時段
資料日期 擷取日 2026-11-26 對外發布前再查一次，保留查核日期

若要做「週六晚上看展」的小卡，文案可寫「官方一般開放時間目前列為週六至 20:30；出發前請查當日公告」。這句話保留來源與時間條件，比直接寫「每週六營業到八點半」安全。若頁面上有圖片中的備註、票價另頁或展館臨時關閉訊息，Markdown 可能無法替你解釋它們與一般時段的關係，須人工看原頁。

一個三欄證據表怎麼省時間

接案整理活動資訊時，每次修改都有人問「這個時間從哪裡來？」你若只留一段 AI 摘要，就要重新找整頁。保留來源 URL、擷取日期和原頁核對結果，下一次只需回查變動欄位。估算是否省時，可記錄第一次建表的時間、每週複核分鐘數、抓取費與錯誤修正時間；沒有這些紀錄，不能聲稱某個省時百分比。

對需要高度即時的資料，設定一個有效期限。例如活動前一天重新檢查官方網站，若網站回 404、內容與表格衝突或日期未明，就把欄位標記「待確認」，不要靜默沿用舊值。若來源是社群貼文或第三方轉載，應再找主辦方的原始公告，並在表中明確記錄哪個來源負責哪項資訊。

這套方法的重點不是多抓幾次，而是讓每個對外數字能回到原發布單位與查核日期。Firecrawl 的結果幫你建立可搜尋的草稿，最後採信什麼仍由編輯決定。下一篇改從不知道網址的 Search 工作開始，避免一開始就拿轉載當原始資料。

把「一般開放時間」與「當天能不能去」分開

美術館的固定時段是參觀指南的一個欄位，並不是完整的到訪決策。展覽可能有自己的入場截止時間，館方可能因國定假日調整營運，戶外空間與售票口也可能不同。若讀者問「這週六晚上七點能進去嗎」，你需要確認的是當週公告及該展覽的入場規則；單一開放時間頁只能支持一般時段。將問題拆開，才能避免過度引用一個頁面。

同樣的核對表可加一欄「下次重查時機」。固定資訊或許每月複核即可；活動前一天、售票前或對外發送電子報前要即時重查。若有兩個來源彼此衝突，不要任意選較新的搜尋摘要，應打開館方原頁與公告，記錄衝突並暫緩發布該欄。這個暫緩狀態要在工作表裡看得見。

若要做多館比較，每館使用同樣欄位，但不要把缺值填成「休館」。未找到、官網未提供、抓取失敗和明示休館是四種不同狀態。對讀者而言，表格中的一個空格可能意味著白跑一趟；把缺值標清楚，才真正減少客服追問和後續改稿。來源 URL 也應指向具體時段頁，不只放網站首頁。

完成初稿後讓另一人照表中的 URL 回查兩個高風險欄位，例如休館日與週六時間。如果第二人無法在原頁找到同一條資訊，就說明表的來源定位不夠清楚。這比讓第二人只讀摘要更能測出錯誤，也能累積下次製作參觀指南的查核範本。

如果表格將用在手機上的參觀卡，建議把一般時段與資料日期一起顯示，並提供通往官方時段頁的連結。讀者在現場看到公告不同時，至少知道去哪裡核對。對作者來說，這也降低了每次網站改動都需重新發一份完整指南的壓力。
