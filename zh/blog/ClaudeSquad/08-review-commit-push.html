Claude Squad Review、Commit、Push：代理人跑完之後的完整審查流程

2026 年 5 月 23 日·6 min read

代理人跑完任務，這才到了最重要的一步——你要確認它做了什麼。

這不是多此一舉。代理人有時候做的比你要求的多，有時候做的方向跟你預期的不一樣，有時候改了一個你沒注意到的地方。Review 這道關卡，是你和代理人工作流裡的最後防線。

Claude Squad 的設計讓這件事變得很順——不需要切換到別的終端機視窗，不需要手動跑 git diff，直接在 TUI 裡就能完成整個審查到推送的流程。

審查流程總覽

一個完整的審查流程分四個步驟：

  1. 查看 diff：在 TUI 裡看代理人改了什麼
  2. 確認沒問題：人工判斷改動在預期範圍內
  3. Checkout（選用）：把改動暫存到 branch，暫停 session
  4. Push：把 branch 推到 GitHub，開 PR

步驟一：查看 Diff

選中想查看的 session（用 ↑/↓），然後按 tab 切換到 diff 模式。

右側預覽區會顯示這個 session 的 git worktree 相對於原始 branch 的所有變更——格式就是標準的 git diff，新增的行是綠色，刪除的行是紅色。

Diff 比較長的話，用 shift-↑ 和 shift-↓ 捲動。

審查時要注意的幾件事

改動的範圍：代理人有沒有改到你沒預期的檔案？如果它本來只應該改 UserService.ts，卻動了 AuthController.ts，你要搞清楚它為什麼這樣做。

新增 vs 刪除的平衡：如果代理人刪了很多行而沒有相應的新增，確認它不是在幫你「簡化」你其實需要保留的邏輯。

測試有沒有更新：代理人改了邏輯，測試有沒有跟著更新？改了函式簽名，呼叫的地方有沒有全部更新？

引入了什麼新的依賴：有沒有新的 import，這些依賴你接受嗎？

步驟二：如果需要補充或修正

看 diff 的時候發現有問題，按 ↵ 附加進那個 session，直接補充指令給代理人：

你在 UserService.ts 第 45 行用了 any 型別，
幫我換成正確的型別定義，類型可以參考 src/types/User.ts

代理人修正之後，ctrl-q 退回 TUI，再按 tab 重新看 diff。

步驟三：Checkout（提交並暫停）

確認這個 session 的改動沒問題，按 c 做 checkout。

這個操作做了兩件事：

  1. 把這個 session 目前所有未提交的變更 commit 到它的 branch
  2. 把 session 標記為「暫停（paused）」狀態

Checkout 之後，這個 session 的改動就安全地存在它的 branch 上了——就算你之後刪掉 session，branch 還在。

如果你之後想繼續讓代理人在這個任務上工作，按 r 恢復 session，它會繼續從上次暫停的地方繼續。

步驟四：Push 到 GitHub

確認沒問題，按 s push。Claude Squad 會：

  1. 確保所有改動都已 commit（如果還沒，會自動 commit）
  2. 把這個 session 的 branch push 到 GitHub 遠端

Push 完成之後，去 GitHub 開 PR 就好。每個 session 對應一個 branch，每個 branch 開一個 PR——清楚、可追蹤、review 起來不混亂。

替代方案：用 git 指令手動操作

如果你偏好直接用 git 指令，也完全沒問題。Claude Squad 的 worktree 就是標準的 git branch，可以用任何 git 工具操作：

這和在 TUI 裡按 s 效果一樣，只是手動。

常見問題

Q：Push 的時候出現 gh: command not found

gh CLI 沒裝或沒加到 PATH，回去看安裝篇的前置工具設定。

Q：Push 之後看不到 branch

確認你的 git remote 設定正確，用 git remote -v 確認有沒有 origin。

Q：代理人改的東西我不滿意，要怎麼全部放棄？

直接在 TUI 按 D 刪除那個 session——對應的 worktree 會清掉，改動不會影響你的主 branch。這是 worktree 隔離帶來的好處：放棄成本幾乎是零。
