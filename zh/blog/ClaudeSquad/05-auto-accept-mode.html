Claude Squad Auto-Accept 模式：讓代理人安靜跑完，你去做別的事

2026 年 5 月 16 日·6 min read

讓代理人跑任務的時候，有一件很煩的事——它中途遇到確認提示，停下來等你回答：

確定要刪除這個檔案嗎？(y/n)
是否繼續？(y/n)

如果你就在旁邊，還好，按個 y 繼續。但如果你的初衷是讓代理人跑在背景，你去做別的事——這種中斷就很痛苦。你要一直盯著，或者等你回來的時候發現它停在那邊等你，什麼都沒跑。

Auto-accept 模式就是為這個設計的。

怎麼開啟 Auto-Accept

啟動 Claude Squad 的時候加上 -y 旗標：

開啟之後，這個 cs 程序管理的所有 session 都會自動接受代理人的確認提示，不會停下來等你。

或者，如果你只想讓特定 session 跑在 auto-accept 模式，可以在建立 session 的時候指定——這個功能讓不同任務有不同的自動化層級。

這個模式在做什麼

-y 旗標讓 Claude Squad 在背景自動回應代理人遇到的互動式提示。

對於 Claude Code 來說，這相當於它的「yolo mode」——代理人不需要暫停等待你的確認，直接繼續執行下去。對於 Aider 這類工具，效果類似，會自動確認需要人工輸入的地方。

結果是：你開了任務，走開去做別的事，代理人安靜地跑完，不需要你在旁邊守著。

什麼情境適合開

適合 auto-accept 的任務類型：

  • 任務描述非常明確、範圍清楚——你知道代理人只會改哪些地方
  • 低風險的任務：寫文件、寫測試、加 comment、格式化程式碼
  • 你已經跑過類似任務、大概知道代理人的行為模式
  • 任務在隔離的 worktree 裡跑，就算改錯了，merge 之前你會 review

適合 auto-accept 的工作情境：

  • 你有多個任務要並行跑，沒辦法每個都在旁邊守
  • 任務預計要跑比較久（超過 10 分鐘），你想去做別的事
  • 這是一個「先讓它跑，之後我再審查 diff」的工作流

什麼情境不該開

不適合的任務：

  • 任務描述模糊、邊界不清楚——代理人可能會往你沒預期的方向走
  • 會對資料庫、外部 API 或生產環境做操作的任務
  • 高風險的重構——代理人改了很多地方，你需要在關鍵節點確認

不適合的工作情境：

  • 你是第一次嘗試這類任務，不確定代理人會怎麼做
  • 任務結果很難回復（例如批次刪除檔案）

說穿了，auto-accept 是「你對這個任務有把握」的模式——不是「你懶得看」的模式。每次代理人自動略過一個確認，就是你默默承擔了那個決策。

然後在 TUI 裡：

結合背景執行的最佳實踐

Auto-accept 模式讓代理人能無阻礙地跑，但你還是要做 code review——只是時機從「中途確認」改成「事後審查」。

幾個習慣可以讓這個流程更安全：

任務描述要夠具體：「幫我寫測試」比「優化程式碼」安全十倍——前者範圍清楚，後者不知道代理人會改哪些地方。

善用 diff 視圖：代理人跑完之後，在 Claude Squad 的 TUI 裡按 tab 看 diff，確認改動在你預期的範圍內再 merge。

先在小任務上練手：第一次用 auto-accept，選一個範圍小、影響有限的任務——感受一下代理人在這個模式下的行為，再逐漸擴大使用範圍。

Auto-accept 讓背景執行成為可能，也讓真正的並行開發工作流成為可能。下一篇就要講那個工作流——同時跑多個代理人，怎麼安排才不亂。
