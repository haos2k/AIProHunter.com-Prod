Gstack 入門課：把 Claude Code 變成你的虛擬開發團隊

2026 年 4 月 19 日·6 min read

用 Claude Code 寫程式，寫到第二週，你大概就會發現一個問題：AI 很聽話，但它不會問你「你確定要這樣做嗎？」

你說加一個功能，它加。你說重構這段邏輯，它重構。你說把這個 endpoint 修掉，它修——然後引入兩個新 bug，你還要再花三輪對話幫它收尾。

問題不在 Claude 不夠聰明。問題是你一直讓它用同一個腦袋做所有事：產品判斷、架構設計、程式碼審查、測試、部署——全部混在一個 context 裡，一個對話打天下。

Gstack 要修的，正是這件事。

這個系列在解什麼問題

Gstack（全名 GStack）是 Y Combinator CEO Garry Tan 開源的 Claude Code skills 框架。核心概念只有一句：

「Planning is not review. Review is not shipping. Founder taste is not engineering rigor. If you blur all of that together, you get a mediocre blend of all four.」

翻成白話：讓 AI 在對的時間用對的腦袋，不要讓它一個模式打到底。

Gstack 提供九個 skill，分別對應軟體開發週期中的不同角色：CEO 思維的產品決策、工程師視角的架構設計、偏執型資深工程師的程式碼審查、自動化 QA 測試、一鍵部署——每個 slash command 背後，都是一個切換好的認知模式。

這個系列就是把這套框架，從安裝到真實場景，六篇說清楚。

這個系列適合誰

  • 已經在用 Claude Code 寫程式，但輸出品質不穩定、常常要反覆修的人
  • 想在 review、測試、部署這幾個環節減少人工介入的工程師
  • 一個人做產品，想把 AI 從「打字工具」升級成「虛擬開發團隊」的獨立開發者
  • 看過 Garry Tan 每週 10,000 行程式碼的數字，想知道他到底怎麼做到的人

如果你還沒用過 Claude Code，這個系列對你來說可能會跳太快——建議先把 Claude Code 本身跑熟再回來。

系列閱讀地圖

這六篇從「為什麼需要 Gstack」出發，經過安裝、各個核心 skill 的詳細解說，最後落在真實開發場景的整合示範：

1. 為什麼 AI 助手需要「角色切換」？Gstack 的核心邏輯 先建立心智模型——Gstack 解決的不是 AI 不夠強的問題，而是「沒有給 AI 正確的認知模式」的問題。讀完這篇，你會知道為什麼九個 skill 比一個萬用提示詞更有效。

2. Gstack 安裝與快速上手：10 分鐘讓九個 skill 就位 從 GitHub clone 到 setup 完成，附上常見安裝問題的解法。讀完就能跑第一個 slash command。

3. Plan Review 雙模式：CEO 思維 + 工程師架構，為什麼要分開用 /plan-ceo-review 和 /plan-eng-review 是 Gstack 最高密度的價值所在——一個問你「該不該做」，一個問你「怎麼做才對」。這篇說清楚兩者的差異和使用時機。

4. Code Review 與 Ship：從偏執審查到一鍵交付 /review 找的是那些能過 CI 但會在 production 爆掉的問題。/ship 把 sync、test、push、PR 壓縮成一個指令。這篇解釋它們的內部邏輯和搭配方式。

5. QA 與 Browse：給 AI 一雙眼睛，讓它真的「看到」你的 app /qa 分析你的 git diff、找出受影響的頁面、測試、修 bug、再驗證——輸出一個 0 到 100 的健康分數。/browse 讓 AI 用真實瀏覽器點你的 app。這篇說明它們為什麼值得你花時間設定。

6. 真實開發場景：從新功能到 production 的 Gstack 完整工作流 把前面五篇的概念接在一起，用一個真實場景示範整個流程——從 /plan-ceo-review 開始，一路跑到 /ship 結束。

建議閱讀順序

1 → 2 → 3 → 4 → 5 → 6，照順序讀最穩——概念站穩再安裝，安裝完再用各個 skill，最後把整條流程跑一遍。

時間有限的話：至少讀 1（知道為什麼需要它）和 2（讓工具真的裝起來）。其他篇看你的需求跳讀，3 是最高投報率的一篇，建議不要跳過。

快速上手版本

一句話版本：安裝 Gstack → 新功能先跑 /plan-ceo-review + /plan-eng-review → 實作完跑 /review → 沒問題跑 /ship。

就這樣。細節和各種邊界情況，六篇負責。這篇的任務只有一個：讓你知道地圖長什麼樣子，然後選一條路出發。
