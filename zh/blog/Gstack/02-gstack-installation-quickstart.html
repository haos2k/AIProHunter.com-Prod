Gstack 安裝與快速上手：10 分鐘讓九個 Skill 就位

2026 年 4 月 19 日·6 min read

很多工具的「安裝指南」是這樣的：十個步驟，第七步出錯，然後你開始 Google 錯誤訊息，兩小時後還沒跑起來。

Gstack 不是這樣——安裝真的只有兩個指令，而且整個過程 Claude 自己會跑完。

唯一的前提：你需要 Claude Code、Git、以及 Bun v1.0+。如果這三個都有，直接往下看。

個人安裝（最常用的方式）

打開 Claude Code，貼上這個指令讓 Claude 跑：

Claude 會幫你：

  • Clone 整個 repo 到 ~/.claude/skills/gstack/
  • 為每個 skill 建立 symlink
  • 編譯 /browse 所需的 Chromium binary（約 58MB，macOS / Linux 均支援）
  • 安裝 node_modules

整個過程大約 2-5 分鐘，主要在等 binary 編譯。不需要設定 PATH，不需要 sudo——所有東西都放在 .claude/ 裡面。

確認安裝成功

安裝完，在 Claude Code 裡輸入任意一個 slash command 試試：

/plan-ceo-review

如果 Claude 開始問你「你要評估什麼功能或想法？」這類問題，代表安裝成功。

常見問題

Q：./setup 跑到一半卡住？
通常是在編譯 binary 的時候。確認 Bun 是 1.0 以上版本，如果是舊版先升級：bun upgrade。

Q：/browse 安裝了但 Chromium 啟動失敗？
確認是 macOS 或 Linux（x64 / arm64）。Windows 目前不支援 /browse 和 /qa 的瀏覽器功能，其他 skill 可以正常使用。

Q：想更新到最新版本？
在 Claude Code 裡跑 /gstack-upgrade，它會自動偵測你的安裝方式（全域或 repo 內），升級並告訴你改了什麼。

Q：token 消耗比想像中高？
Gstack 的每個 skill 都有一定的 context 初始化成本，複雜的 review 任務可能燒 10K+ tokens。建議選擇性使用，不需要每個 skill 都開——新功能開發用 /plan-ceo-review + /plan-eng-review，上線前用 /review + /qa，夠了。

安裝完，最該先做的三件事

1. 跑一個 /plan-ceo-review 感受一下

找一個你最近在考慮要做的功能或決策，不用很正式，就說「我想幫我的 app 加一個通知系統」，然後看 Gstack 的 CEO 模式是怎麼回應的。

跟你習慣的 Claude 對話會有明顯差異——它不會直接說「好，這樣設計」，而是會先問你幾個你可能沒想到的問題。

2. 試試 /review 在一段真實的程式碼上

選一段你覺得「大概沒問題」的程式碼，丟給 /review 看看。很多人第一次用都會有點驚訝——它找到的問題不是拼字錯誤，而是那些「平時不會注意，但在高流量下會爆掉」的類型。

3. 設定 /setup-browser-cookies（如果你要用 /qa）

如果你的 app 有登入功能，在跑 /qa 之前要先用這個指令把你的 session cookies 匯入——不然 AI 測試的全是未登入頁面，測不到重要的功能。

這個步驟很快，它會開一個互動式的 picker 讓你選要匯入哪些 domain 的 cookies，整個過程 cookie 值不會顯示在畫面上。
