Deep Agents CLI：終端機裡有一個真正會規劃的 Coding 代理人

2026 年 4 月 24 日·7 min read

前八篇把 Deep Agents SDK 的核心能力都拆開來說了——規劃、Filesystem、後端、Subagents、記憶、Skills。

這篇來看 SDK 的一個具體實作：Deep Agents CLI——一個直接跑在你終端機裡的 coding 代理人。

不需要自己建代理人、不需要寫 create_deep_agent()，裝好後直接用。

什麼是 Deep Agents CLI

CLI 是在 deepagents SDK 上建的一個 coding 代理人，開箱即有 SDK 的完整能力：

  • write_todos 自動規劃任務步驟
  • Filesystem 工具 管理 context 和中間產物
  • 長期記憶 跨 session 記住你的偏好和專案狀態
  • Skills 支援 載入你定義的規範文件
  • Sandbox 執行 在隔離環境裡跑程式碼

它不只是「在終端機裡的 ChatGPT」，是一個有完整代理人基礎設施的 coding 助理。

安裝與啟動

第一次啟動會有初始化設定流程，選擇要用哪個 LLM 後端（OpenAI、Anthropic、Ollama 等都支援）。

基本使用方式

啟動後就是互動式對話，直接輸入你要做的事：

> 幫我重構 src/utils.py，把重複的邏輯抽出來，加上 type hints

> 分析這個 codebase 的架構，給我一份說明文件

> 幫我寫一個 REST API endpoint，處理用戶登入，要有 JWT 驗證和錯誤處理

代理人會：

  1. 先列出執行計畫（write_todos）
  2. 讀取相關的程式碼（Filesystem read_file）
  3. 執行修改或新增
  4. 跑測試確認沒有問題（如果你有設定 Sandbox）
  5. 回報完成結果

  • 直接執行你的程式碼驗證輸出

  • 在隔離環境裡嘗試不同的實作方式

比起「讓代理人生成程式碼，然後你自己去跑看看」，能直接執行讓整個開發循環快得多。

Human-in-the-Loop：不確定的事情先問你

CLI 支援 human-in-the-loop 機制——代理人在某些情境下會暫停來問你：

  • 任務範圍不明確的時候（「你是要重構整個 src/ 還是只有 utils.py？」）
  • 有破壞性操作的時候（「這個操作會刪掉 config.json，確定繼續嗎？」）
  • 遇到需要你做判斷的選擇（「這裡有兩種實作方式，你偏好哪一種？」）

這個設計讓代理人在有把握的地方自己做，在有疑慮的地方不亂猜——不是什麼都問你（那就只是個聊天機器人），也不是什麼都自己決定（那就容易出岔）。

CLI vs. SDK：什麼時候用哪個

Deep Agents CLI Deep Agents SDK
適合場景 個人開發助理、互動式 coding 建立產品、自訂 agent 行為
上手速度 裝好即用 需要寫程式設定
客製化程度 Skills + 設定檔 完全可程式化
工具整合 內建 coding 工具 任意自訂工具
使用方式 終端機互動 invoke / stream API

簡單說：CLI 是給你自己用的，SDK 是給你拿去建產品的。

一句話說清楚

Deep Agents CLI 是這個系列所有能力的收尾——把規劃、Filesystem、記憶、Skills 全都整合進一個可以直接在終端機用的 coding 代理人。

不需要建基礎設施、不需要寫 boilerplate，裝好設定 skills，然後告訴它你要做什麼。
