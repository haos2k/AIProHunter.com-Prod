Superpowers 入門課：5 篇文章帶你搞懂 Skills、流程與 AI Agent 工作方式

2026 年 3 月 29 日·5 min read

這裡是 Superpowers 系列的首頁：不會在這一篇塞滿所有知識細節，而是幫你認路、排順序，然後一鍵跳到對的那一篇。可以把 AI Agent 想成充滿幹勁的超強AI開發團隊，但前提是——你得先告訴它「照哪條跑道衝」，不然機房裡很快就會充滿熱情與雞毛。

為什麼這個系列值得讀

Superpowers 不是在堆更多屎山代碼，而是在固定一條工作節奏：先理解與設計，再規劃與實作，最後驗證。很多新手痛點不是模型不聰明，而是一上來就寫程式開幹、跳過釐清，結果改三次還在原地打轉。這個系列把「該先叫哪個 skill、什麼時候該停一下想設計」拆成五篇較短文章，讀完你會有一套可重複的套路，而不是零散技巧。

這個系列適合誰

  • 剛開始用 Agent、Skills，聽過 Superpowers 但不知道從哪篇下手的人
  • 已經會下指令，但常覺得代理「很拼卻常跑偏」，想補上流程與品質觀念的人
  • 想把 spec / plan / 實作 / 驗證 分清楚，避免每次都從零摸索的人

若你只想找「一句話版」的捷徑，可以直接跳到文末的 快速上手版本；要扎實一點，就照建議順序把五篇文章讀完。

系列閱讀地圖

整條路可以想成一條線：先懂規則與世界觀 → 再學「開工前為什麼要先設計」→ 接著是 spec、plan、implementation 怎麼接起來 → 然後補上三個品質 → 最後落到真實工作場景（新功能、修 bug、收尾）。下面每一篇都是地圖上的一站，點進去就有該站的重點教學。

5 篇文章你會學到什麼

  1. Superpowers 是什麼？先搞懂 Skills 工作流的核心規則
    導讀： 建立共同語言——Superpowers 在解什麼問題、哪些規則是硬底線，讀完你才會知道後面每一篇為什麼這樣排。

  2. using-superpowers 與 brainstorming：為什麼不能跳過設計直接開工
    導讀： 把「先想清楚再動手」變成可執行步驟；這篇負責堵住最常見的坑——需求還在雲裡霧裡就開始寫實作。

  3. spec、plan、implementation 有什麼差別？Superpowers 的正確落地流程
    導讀： 釐清三個階段的產出與邊界，讓代理照著階段走，而不是把規格、計畫和程式碼糊成一團。

  4. TDD、systematic-debugging、verification-before-completion：AI Agent 的三道品質把關
    導讀： 在實作與交付前加上測試、除錯與驗證的步驟，降低「看起來做完了其實沒過關」的風險。

  5. 新功能、修 bug、收尾交付：Superpowers 在真實工作的使用套路
    導讀： 把前面學到的流程對應到日常任務類型，讓你知道今天這張工單該從哪個 skill、哪種順序開場。

建議閱讀順序

建議照 1 → 2 → 3 → 4 → 5 讀：規則與世界觀先打底，再談開工前的 brainstorming，接著是 spec / plan / implementation 的接力，然後補品質把關，最後用真實工作流把整條線串起來。若你時間真的很少，至少讀 1 與 3，再視情況補 4；有餘力再回頭補 2 與 5，印象會更牢。

快速上手版本

一句話：有對應的 process skill 就先走流程，再讓實作進場；寫完要能說得出你驗證過什麼。
若你只能記三個關鍵字，就記 brainstorming（或釐清）、writing-plans（或計畫）、verification-before-completion（或驗證）——分別對應「別瞎衝」「別亂改」「別假裝做完」。細節與時機請交給上面五篇；這一篇的任務到此為止：認路、排程、出發。
