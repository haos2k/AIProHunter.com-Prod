Superpowers 是什麼？先搞懂 Skills 工作流的核心規則

2026 年 3 月 29 日·6 min read

如果你剛開始用 AI Agent、又聽過「Superpowers」這套東西，心裡大概會冒出一個很合理的問題：這到底是外掛、還是又一包提示詞？先講結論：它比較像一組「先走哪條路」的習慣與規則，搭配一疊寫好的 Skills（技能說明檔），讓代理不要一進場就亂衝。這篇只負責把定位與鐵律講清楚，讀完你就能判斷「現在該叫誰上場」。

Superpowers 的定位

可以把 Superpowers 想成：在 AI 代理幫你寫碼、改架構、跑指令之前，先幫你把「工作順序」定下來。它不是換一個更聰明的模型，而是告訴AI Agent：哪些情境要先釐清、哪些要先規劃、哪些要先測再說「做完了」。

對初學者來說，最有感的差別是這個：沒有流程時，你常覺得AI Agent「很拼命」但結果極度不穩定，結果有高度不可控性；有流程時，代理可能話變多、步驟變清楚，但少了很多返工與心累。Superpowers 就是在推後面這種節奏。

為什麼它不是海量提示詞工程

海量提示詞工程通常是「一段很長的咒語」，希望模型一次就懂你要什麼。Superpowers 比較像 把大任務拆成固定階段，每個階段有對應的 skill 可以叫出來用。

差別在於：咒語再長，也沒辦法保證代理會記得「先問需求、再寫計畫、最後才動手」；而 skill 是把那段行為寫進系統規則裡，變成「有這個檔案、就照這套劇本演」。所以它不是「多幾句話變強」，而是「多一條跑道，少很多次跑偏」。

核心規則與鐵律

下面幾條可以當成新手版口訣，之後你在系列其他篇會一再看到它們的影子：

  1. 有對應的流程型 skill，就先走流程。 不要心裡覺得「這次很簡單」就跳過；簡單任務跳過的代價，常常是後面多花三倍時間擦屁股。
  2. 不要預設代理已經懂你的專案。 上下文要補、需求要講；流程 skill 的存在，很大一部分就是在逼這件事發生。
  3. 實作很香，但順序錯了會變苦。 先搞清楚「要做什麼、做到哪裡算停」，再讓雙手去碰鍵盤，整體會順很多。

這些聽起來像碎碎念，但真的是新手最容易踩的洞：不是模型不聰明，是我們太急著開工。

Process skill vs Implementation skill

用白話分兩類就好：

  • Process skill（流程型）：管的是「現在該做哪種思考與產出」。例如先探索需求、先腦力激盪、先寫計畫、先決定怎麼驗證——重點是 把路走對。
  • Implementation skill（實作型）：管的是「怎麼把東西真的做出來」。例如照著計畫改程式、補測試、跑指令——重點是 把路走完。

記一個判斷法：如果你心裡的下一步是「先想清楚再動手」，多半是在叫 process；如果已經有共識、只差把碼寫進去，才是 implementation 的主場。兩邊不是誰比較厲害，而是 誰先誰後 的問題——順序對了，實作 skill 才發揮得了全力。

常見誤區

  • 「我問題很小，不用走 skill。」 小問題最常見的死法，是代理誤會一個小詞，然後改錯檔、改錯行。流程不是大題專用，是 防呆專用。
  • 「我把需求講超細，就可以跳過 brainstorming。」 講得細很好，但 「講了」不等於「雙方對焦完成」。流程 skill 常常就是在做對焦與確認，不是重複聽你唸一次。
  • 「Superpowers 會讓代理變慢。」 短期對話步數可能變多，但整體工時常常變少，因為少了很多「以為做完其實沒做完」的來回。

如果你發現自己一直在同一個功能上繞圈，先別急著換模型——值得先問自己：我是不是跳過了某個流程？
