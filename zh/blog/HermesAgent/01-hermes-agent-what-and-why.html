Hermes Agent 是什麼？跟 Claude Code、Cursor 差在哪裡

2026 年 4 月 19 日·8 min read

很多工具都說自己是「AI Agent」——有的是指 LLM 幫你寫程式，有的是指一個有工具存取權的聊天視窗，有的是指一套跑在 CI 上的自動化流程。這些定義互不相干，但都掛著同一個名字。

Hermes Agent 的定義比較接近：一個跑在你機器上的 AI Agent 運行環境，有工具、有記憶、有 Skills、能多平台、能排程——重點是這些東西全部整合在一起，而不是散落在三個不同的插件裡。

這篇的任務：幫你建立基礎世界觀，讓你知道 Hermes 在解什麼問題、架構長什麼樣、跟你可能已經在用的工具差在哪裡。

你在用的工具解的是哪一層問題

先說清楚幾個名字，避免後面混淆。

Claude Code / Cursor / Windsurf 解的是「在 IDE 裡有 AI 幫你寫程式」的問題。它們的核心場景是：你在一個代碼庫裡，AI 讀你的文件、改你的程式碼、幫你跑測試。它們很強，但基本上是 IDE-bound——離開那個視窗，代理就沒了。

Superpowers / Gstack / GSD 解的是「怎麼讓這個 AI Agent 走正確的流程、問正確的問題」——它們是 skills 和工作流的套件，寄生在 Claude Code 上面跑，不是獨立的 Agent 環境。

Hermes Agent 解的是另一個層次的問題：AI Agent 應該住在哪裡、應該怎麼長期存在、應該怎麼在不同平台和任務之間保持一致性。

跑在 CLI，也能跑在 Telegram、Discord、API Server。記憶跨 session 持久。Skills 是獨立的知識文件，可以自己安裝、分享、升級。任務可以排程在凌晨自動跑。子代理可以平行執行。

這不是「更好的聊天視窗」，是一個更底層的基礎設施。

Hermes Agent 的核心架構

你可以把 Hermes 想成三層疊起來的東西：

第一層：工具層（Tools & Toolsets）
這是代理能做到的事——搜尋網路、執行終端指令、操作瀏覽器、讀寫文件、產生圖片、發送訊息。每個工具是一個 function，打包成 toolset，可以按平台或場景開關。

跑 hermes tools 就能看到有什麼、開了什麼、怎麼配置。你可以指定「這個 session 只開 web 和 terminal，不要開 browser」——token 節省，行為更可預測。

第二層：記憶層（Memory System）
兩個文件，MEMORY.md 和 USER.md，存在 ~/.hermes/memories/，每次 session 開始時注入到 system prompt。

MEMORY.md 是代理的個人筆記：「這台機器跑 Ubuntu 22.04，Docker 裝好了，SSH port 是 2222 不是 22」。
USER.md 是你的 profile：「這位用戶喜歡簡短回答，討厭過度解釋，主要語言是 TypeScript」。

重點是：你不用每次都重新交代。代理記得。

第三層：Skills 系統
這是 Hermes 最特別的設計，後面會有整篇專門講。簡單版：Skills 是一份份 Markdown 文件，告訴代理「在這種情境下，應該照這個流程走」。每個 skill 自動變成一個 slash command。

Skills 不是 prompt，不是插件——是可安裝、可分享、可由代理自己創建的程序性記憶。

跟 Claude Code 的實際差別

這是最常被問到的問題，直接對比說清楚：

維度 Claude Code / Cursor Hermes Agent
運行環境 IDE 視窗內 CLI + 多平台（Telegram、Discord、API）
記憶 無跨 session 記憶 持久 MEMORY.md + USER.md
Skills 依賴外部 skill 套件（如 Superpowers） 原生 Skills 系統，可自建可安裝
排程 無 原生 Cron 排程任務
子代理 無原生並行 最多 3 個子代理同步執行
LLM 支援 通常綁定特定模型 支援任意提供商，可配置 fallback
部署場景 開發機上 開發機、伺服器、Telegram bot

Hermes 打不過 Claude Code 的地方：IDE 整合深度。如果你主要工作是在一個代碼庫裡寫程式，Claude Code 跟代碼庫的整合還是更緊密——diff 預覽、file context、inline 編輯這些體驗更流暢。

Hermes 贏的地方：你想讓 AI Agent 做的事不只是「在這個代碼庫裡寫程式」——你想讓它每天早上自動幫你整理昨天的新聞、在 Telegram 上回應你的指令、凌晨跑一批資料處理任務、而且還記得你上週說「不要用 sudo 跑 Docker」。

一句話定位

Hermes Agent 不是「更好的 Cursor」，也不是「更強的聊天機器人」——它是把 AI Agent 從 IDE 視窗解放出來的基礎設施，讓你能把 AI 的能力部署到更多地方、讓它跨 session 保持記憶、讓它的行為靠 Skills 而不是靠你每次重新交代來決定。

如果你現在的工作流 100% 是在 IDE 裡寫程式，Hermes 可能不是最急迫的投資。

但如果你開始覺得「每次跟 AI 對話都要重新交代背景」、「我想讓這個任務自動在凌晨跑」、「我想在 Telegram 上也能叫到同一個 AI」——Hermes 解的就是這些問題。
