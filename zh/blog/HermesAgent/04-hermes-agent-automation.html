Hermes Agent 自動化：Cron 排程、子代理並行、Code Execution 三招

2026 年 4 月 19 日·8 min read

大多數 AI 工具的使用模式是：你問，它答，然後就結束了。

這個模式有個硬限制：你必須在場。你不問，任何事都不會發生。想讓 AI 在你不在的時候做事，或者同時跑幾條平行任務線，通常要繞很複雜的路。

Hermes Agent 把這個限制正面破解了。這篇講三個核心自動化能力：Cron 排程、子代理並行（Delegation）、和 Code Execution。

Cron 排程：讓任務自己在凌晨跑

設定完就結束了。之後每天早上 8 點，Hermes 自己起來執行這個任務——不需要你在場，不需要你開 session，不需要你打任何字。

Cron 任務可以帶 Skill

這裡有個很關鍵的整合：Cron 任務可以附帶 skill 執行。

這讓 Cron 從「排程跑一個 prompt」升級成「排程跑一套流程」——skill 的步驟邏輯、已知的坑、驗證方式，全部帶進去。

Delegation：一件事交給三個子代理同步做

delegate_task 工具讓代理可以生出最多 3 個子代理，各自跑獨立的任務——有自己的 context、自己的 toolset、自己的 terminal session。

最直接的使用場景：需要平行研究多個主題。

三個子代理同時搜尋，主代理等它們完成後彙整——整體時間是「最慢那個子代理的時間」，而不是「三個加起來的時間」。

子代理的特性

  • 隔離的 context：子代理不知道主對話的內容，只知道被分配的任務
  • 可限制的 toolset：可以指定子代理只能用哪些工具（例如只給 web 搜尋，不給 terminal）
  • 獨立的 terminal session：子代理跑指令不會影響主代理的工作目錄

這個隔離設計很重要——你可以放心讓子代理跑一些有副作用的操作（例如測試部署到 staging），不用擔心它搞亂主環境。

什麼時候用 Delegation

適合：

  • 獨立的平行研究任務（三個不同主題同時搜尋）
  • 隔離環境的操作（一個測試 A 方案，一個測試 B 方案）
  • 有明確邊界的子任務（先讓子代理寫前端，自己負責後端）

不適合：

  • 任務之間有強依賴的（A 要先完成才能做 B）
  • 需要大量共享狀態的（子代理之間溝通成本很高）
  • 簡單的序列任務（用 Delegation 反而更慢）

Code Execution：把多步流程壓成一個 LLM turn

這是 Hermes 自動化能力裡最技術的一塊，但也是效率提升最顯著的。

普通的工具調用是這樣：每個工具調用都是一個 LLM turn——代理調用工具 A，等結果，看結果，決定下一步，調用工具 B，等結果，繼續。

execute_code 讓代理可以寫一段 Python 腳本，在這段腳本裡連續調用多個 Hermes 工具——整個多步流程壓縮成一個 LLM turn。

從 LLM 的角度看，這是一個工具調用——但實際執行的是三個搜尋加一個文件寫入。

適用場景

  • 批次資料處理：一次處理一百個 URL、文件、或資料點
  • 帶條件判斷的自動化：「如果搜尋結果少於 3 篇，換關鍵字再搜一次」
  • 多工具串聯：搜尋 → 分析 → 格式化 → 儲存，一次完成

三個能力怎麼搭配

這三個工具設計用來互補，不是互相替代：

能力 解決什麼問題 最適合場景
Cron 你不在場，任務自己跑 日報、健康監控、定期清理
Delegation 同時跑多條平行任務線 平行研究、A/B 測試部署
Code Execution 多步流程效率壓縮 批次處理、複雜資料管道

一個典型的組合：

每天早上 8 點（Cron） → 生出三個子代理（Delegation）→ 各自搜尋一個主題（Code Execution 做批次處理）→ 主代理彙整 → 送到 Telegram。

你設定一次，之後每天自動產出。

跟其他工具的差距

大多數 AI 工具沒有這三個東西的原生整合——要達到類似效果，通常要把 AI API + cron job + 自己寫的 Python glue code 拼在一起，維護成本不低。

Hermes 把它們都做成原生功能，而且跟 Skills 系統和記憶系統整合在一起——排程任務可以帶 skill，子代理可以用主代理的 memory 注入的背景知識，Code Execution 可以調用任何 Hermes 工具。

這整合度，才是自動化能力真正發揮價值的地方。
