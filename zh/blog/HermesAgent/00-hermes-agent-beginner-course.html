Hermes Agent 入門課：5 篇帶你搞懂這個比 Claude Code 更狂野的 AI Agent

2026 年 4 月 19 日·6 min read

你可能聽過 Claude Code、Cursor、Windsurf，甚至 Superpowers——但 Hermes Agent 這個名字，很多人還沒聽到。

這是 NousResearch 做的一個 AI Agent 框架，跑在 CLI、Telegram、Discord，支援任意 LLM 提供商，有一套完整的 Skills 系統（相容 agentskills.io 標準）、兩層持久記憶、子代理並行、Cron 排程任務——光是功能清單就夠讓人看一輪。

這篇不是要把那份清單再貼一遍。這裡是 Hermes Agent 系列的首頁：幫你認路，讓你知道五篇文章各自解決什麼問題，然後按順序讀，或直接跳到你最需要的那站。

為什麼這個系列值得讀

大多數人遇到新 AI 工具的第一個死法，是把文件從頭掃到尾——然後什麼都記不住，因為沒有脈絡。

Hermes Agent 的文件很完整，但「完整」不等於「好進入」。它的核心概念之間有依賴關係：你要先知道 Skills 是什麼，才能理解為什麼 Cron 排程任務可以「附帶 skill 執行」；你要先知道記憶系統的設計邏輯，才能判斷什麼時候應該讓代理存東西、什麼時候讓它搜舊對話。

這個系列把這條依賴鏈拆成五篇，讓你一站一站走，每篇結束都能用，不需要等到全部讀完。

這個系列適合誰

  • 聽過 Hermes Agent 但還沒動手安裝、想先摸清楚值不值得投資的人
  • 已經在用其他 AI 工具（Claude Code、Cursor、Superpowers），想看看 Hermes 有沒有補上什麼缺口
  • 想要一個「不只在 IDE 裡活著」的 AI Agent——能跑 Telegram、能排程、能平行跑多個子任務的人

如果你只是在找「一句話結論」：Hermes Agent 是一個把 AI Agent 部署能力推到 CLI + 多平台 + 長期記憶的框架，Skills 系統是它最核心的差異點。

細節在後面五篇，這裡是地圖。

系列閱讀地圖

整條路的邏輯是：先搞懂 Hermes 在解什麼問題、跟其他工具有什麼差別 → 再深入最核心的 Skills 系統 → 接著是讓 AI 真正「記住你」的記憶層 → 然後是讓任務自己跑的自動化能力 → 最後把一切串成真實工作流。

每篇都是獨立可讀的，但建議第一次照順序走。

5 篇文章你會學到什麼

  1. Hermes Agent 是什麼？為什麼它比你以為的更不一樣
    導讀： 建立基礎世界觀——Hermes 解的問題、核心架構、跟 Claude Code / Cursor 的定位差異。讀完你才不會在後面幾篇迷路。

  2. Skills 系統：讓 AI Agent 在對的時候問對的問題
    導讀： Skills 是 Hermes 最獨特的設計。這篇帶你從「skill 是什麼」走到「如何自己寫一個」，以及 Progressive Disclosure 設計背後的 token 節省邏輯。

  3. 持久記憶系統：讓 Hermes 記住你、記住你的專案
    導讀： MEMORY.md 和 USER.md 的設計哲學、應該存什麼不應該存什麼、跟 session search 怎麼配合——讓代理不再每次都要重新交代背景。

  4. 自動化能力：Cron 排程、子代理並行、Code Execution
    導讀： Hermes 最狂的一層——讓任務自己在凌晨跑、把一個大任務拆給三個子代理同步處理、用 execute_code 把多步流程壓成一個 LLM turn。

  5. 真實工作流：從安裝到每日使用，一個開發者的完整套路
    導讀： 把前四篇學到的東西接到真實場景——日報自動生成、代碼審查流程、多平台交付，以及什麼時候 Hermes 打得過 Claude Code、什麼時候它們應該一起跑。

建議閱讀順序

照 1 → 2 → 3 → 4 → 5 走：世界觀先打底，再學 Skills（這個最重要），接著補記憶系統，然後是自動化，最後用真實工作流收尾。

時間很緊的話，至少讀 1 和 2——Hermes 的核心差異點集中在這兩篇；其他三篇按你的需求挑著看。
