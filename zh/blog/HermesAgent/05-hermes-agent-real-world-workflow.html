場景三：Hermes + Claude Code 一起跑

這是很多人沒想到的組合，但實際上很自然——它們解的是不同層的問題，不是競爭關係。

Claude Code 做的： 在代碼庫裡寫程式——diff 預覽、inline 編輯、file context 整合。IDE 裡的體驗目前還是 Claude Code 更流暢。

Hermes 做的： Claude Code 打不到的地方——跨 session 記憶、排程任務、Telegram 交付、平行子代理、任意 LLM 提供商切換。

實際搭配方式：

或者讓 Hermes 負責「工作之外的 AI 任務」——早晨摘要、週報生成、排程監控——Claude Code 繼續負責日常開發。

你不需要二選一。 它們的定位不重疊，但整合在一起比單獨用任何一個都更完整。

一張清單：你現在就可以做的事

裝好 Hermes 之後，按這個順序推進：

  1. ✅ 安裝，跑 hermes chat，確認基本功能正常
  2. ✅ 設定 LLM 提供商，hermes model
  3. ✅ 看一遍 skill 索引，What skills do you have?
  4. ✅ 告訴 Hermes 你的工作環境，讓它存進記憶
  5. ✅ 設定一個 Cron 任務——哪怕只是每天早上的新聞摘要
  6. ✅ 找一個你常重複做的流程，寫成 skill
  7. ✅ 如果有 Telegram，接上去

不需要全部一次做完。每個步驟都有獨立的價值，做完一個就有一個的回報。

最後一句話

Hermes Agent 的學習成本不低——有 Skills、有記憶系統、有自動化三件套，每個都有自己的邏輯需要理解。

但它解決的問題也是真實的：AI 工具太多，每個都只管一塊，沒有一個在幫你把「AI 的能力」整合成「跨平台、跨 session、有記憶、能排程」的完整代理基礎設施。

Hermes 是目前我看過最接近這個目標的開源框架。學習成本值得投資。
