Orca Worktree 怎麼用？讓三項網站修改各有自己的分支與檔案

2026 年 11 月 22 日·8 min read

同一個咖啡店首頁，兩個視窗竟然長得不一樣：一個預約按鈕能點，卻還寫著 2025 年八折；另一個清掉了舊活動，按鈕卻仍被選單遮住。這不是有人改壞了網站，而是兩個 Orca worktree 各自停在自己的修改進度。看懂這一幕，比先背 Git 術語更有用。

本站這次用虛構咖啡店示範站實際建了三個 Orca 工作區，起點都是同一個 commit c764164。coffee-nav 只改 styles.css，coffee-copy 只改 index.html，coffee-form 只改 app.js。這三項修正都是真實的本機檔案與測試；店家與委託仍是教學虛構，沒有客戶訂單或 AI agent 實跑。

一張分工表先寫好

工作區 允許修改 驗收條件 不在本次範圍
coffee-nav 手機導覽 CSS 390px 預約按鈕可見、可點 更換預約系統
coffee-copy 舊活動區塊 過期資訊消失 自行編新優惠
coffee-form 表單狀態程式 成功、失敗提示不同 真實後端收件

這三行也是最小的審查範圍：A 看 CSS 與手機畫面，B 看舊活動是否消失，C 看表單狀態。若某份 diff 突然出現付款或新優惠，就能在接回主線前停下來。正式接案時，把起點 commit 和負責驗收的人也寫在卡上。

工作區隔離在畫面上長什麼樣？

官方 Worktrees 文件把它講得很清楚：分支指向提交，worktree 是你實際開檔與啟動服務的目錄。Orca 讓每份任務各有目錄和分支，所以 A 的未提交修改不會突然出現在 B。從同一個 commit 起步時，三份內容原本一模一樣；分開改以後，畫面才開始各走各的。

開工前請在分工表寫明 start-from。若 coffee-copy 從較舊版本起步，而 coffee-nav 從較新版本起步，兩份 diff 的基準不同，整合時可能混入早就修過的內容。本站這次讓三個工作區都從 c764164 出發，因此能明確說出每份 commit 只處理一項問題。實際客戶案若已有進行中的 PR，就要先決定新任務從主分支還是該 PR 起步，不能只看工作區名稱。

在 coffee-nav 工作區，手機導覽已改成正常排列，預約按鈕可操作；但首頁仍顯示過期的 2025 年活動。這正是隔離的效果：A 的修正沒有偷帶入 B 的內容。

切到 coffee-copy 工作區，畫面剛好相反：活動文案更新了，舊手機導覽還遮著按鈕。這不是「B 修壞 A」；B 是從同一起點獨立工作，尚未接回 A 的變更。

兩張圖來自 2026 年 11 月 26 日本機 Orca 1.4.256 的工作區瀏覽器，viewport 390×844。它們顯示的是示範站，不是 Orca 設定畫面。照片只能證明當時畫面；按鈕能否點到正確入口仍要做互動檢查。

你可以用一個小練習驗證隔離：在 A 工作區給標題加一個臨時字，切到 B 查看標題是否維持起始版本，再回 A 看改動是否仍在。正式任務不需保留這個臨時字，確認後就丟棄。若 B 也看到 A 的未提交文字，先查兩個終端機是否其實指向同一個目錄；若畫面看到 A 的字、B 的 Git 檔案卻沒有，則應查瀏覽器是否連到 A 的服務。不要立刻叫 agent 重新改標題。

三份修改怎麼接回來？

先看每個工作區的 Git 狀態與 diff，確認只動分工表允許的檔案。本站三個工作區分別提交後，在主分支依序接回三份 commit，沒有遇到文字衝突；合併後重跑四項示範站檢查，全部通過。這只代表本案的三個檔案能順利整合。若兩份任務都修改同一個共用元件，仍可能衝突；即使 Git 沒報衝突，也可能有邏輯上的互相影響。

合併順序可按「風險低、依賴少」來選。本站先接手機樣式，再接文案，最後接表單程式；因為三份修改碰不同檔案，所以順序不是成功的關鍵。但如果 A 與 C 都要改全站按鈕 CSS，就先選一份接回，再讓另一份更新基準、重跑測試。處理文字衝突時，不要只按「接受兩邊」；應對照各任務的驗收條件，決定最後版本要保留什麼。

最後一輪必須在整合後版本跑。A、B、C 各自通過，只能證明它們在各自起點上符合檢查；整合後可能出現共用樣式、路由或設定互相影響。本站四項測試在主分支全部通過，是這個小案例的整合證據。真實網站還需要按實際功能補更完整的測試，不能把四項示範檢查當成全站保證。

本站三個工作區各自提交：導覽 250ad90、文案 e974c23、表單 bafc0ed。接回主分支時形成新的 commit，雖然內容對應，雜湊值不同；交付紀錄應同時留下來源與整合版。這能避免客戶或同事拿工作區 commit 查主分支時以為成果消失。若未來需要回退，也能準確找出要撤回哪一份修改。

用這個方法能省什麼？

三個來源提交是導覽 250ad90、文案 e974c23、表單 bafc0ed；它們接回主線後還要跑一次整合測試。工作區能替你保住清楚的修改邊界，交付前那輪測試仍得自己做。上一篇先準備示範 Repo，下一篇拿導覽這一小項練第一次 agent 任務。
