Orca 第一次 Agent Session：把一個小修改交出去並驗收

2026 年 11 月 23 日·8 min read

第一次叫 agent 修網站，我會把任務壓到一個手機畫面：390px 寬時，預約按鈕別再被導覽蓋住。這樣它交回來的東西才看得完、點得到，也知道該退哪一行。青木咖啡的其他兩個問題先放著，免得「順手」變成沒有邊界的整站翻修。

Orca 第一次操作教學介紹建立工作區與啟動 agent 的流程；支援 agent 清單列出目前可選的工具，選單與登入條件請以你使用的版本為準。本站實際建立了三個 Orca 工作區並手動完成示範站修改，沒有啟動 agent session。以下的指令、回覆與退件是讀者可照做的教學步驟，不能當成本站實測 agent 表現。

先選一個能收得回來的任務

以 coffee-nav 為例，任務不是「把網站變好看」，而是「390px 手機寬度下，導覽不要蓋住預約按鈕，桌面排版與原連結維持可用」。從已知的起點 commit 建工作區，先記目前測試命令。這份示範站從 c764164 起步；起點的四項檢查都會失敗，因為我們故意留了導覽、過期活動與表單問題。只派導覽任務時，後兩項仍紅燈是預期，不要要求 agent 順手修完整站。

在 Orca 選這個工作區，再選自己已安裝並登入的 agent。第一段提示可以直接改寫：

只修 390px 手機版導覽遮住預約按鈕的問題。保留預約連結與桌面資訊架構。請先列出預計修改的檔案與驗證方法；若需要店家新資料，先停下來問。完成後交回 diff、測試命令與結果、仍未驗證的項目。不要修改活動文案或表單。

先看 agent 回的計畫。它若打算換整套 UI 套件或改預約目的地，應在實作前收窄範圍。它若指出遮擋其實來自另一個共用元件，先打開原站核對，再更新任務卡。這一步省的是無效修改與審查時間，不能用「agent 回得快」代替查證。

修改完成後按四層檢查

收到修改後，我會照著畫面走四遍。先看目前是不是 coffee-nav 與正確起點；再看 diff 是否只動導覽；接著在這個目錄跑測試，記下哪幾項仍紅燈；最後開 390px 與桌面畫面，真的點一下預約按鈕。只交一張「看起來正常」的截圖，還不能替代後三步。

本站手動修改的導覽工作區只動了 styles.css，提交為 250ad90。在這個獨立版本的手機預覽中，按鈕不再被蓋住，但舊活動還在，這正是任務邊界。它不是 agent 的成果，卻可以當作你審查第一個 agent 任務時的比對標準。

截圖只能證明指定畫面中的位置關係，無法單獨證明按鈕可點或網址正確。請實際點擊並保留觀察結果。若 agent 在聊天中說「全部通過」，但測試只跑了導覽項，交接卡要照真實結果寫。其餘兩項失敗是任務之外的基準狀態，不必讓導覽任務替它們背書。

交接卡該留下什麼

交接卡不用寫成週報。五行就夠：起點與工作區、允許修改的範圍、實際 commit、跑過的命令與畫面、尚待確認的問題。幾天後你可能已忘了那次聊天，但另一位工程師仍能用這五行把版本找回來。

例如本案可寫：「起點 c764164，工作區 coffee-nav；只修改 styles.css；提交 250ad90；390px 導覽不再覆蓋預約按鈕；舊活動、表單與真實預約收單不在本任務驗收範圍。」若你自己跑出了更完整的點擊測試，再補命令和結果；不要把教學範例的預期寫成已完成實測。

若 agent 建議新增依賴，也要問它解決的是當前遮擋問題，還是只是偏好另一種寫法。新增套件會帶來安裝、版本與維護成本，對一個 CSS 排版錯誤可能不划算。請它先展示最小可行修改和對照畫面；若最小改法會破壞鍵盤操作或桌面版，再討論較大範圍的重構。這種審查不妨礙 agent 提出好建議，卻讓你能控制報價與返工。

第一次卡住時怎麼回退

新 worktree 是另一個目錄，Git 忽略的依賴和環境檔不一定跟過來。啟動失敗時，先分辨是安裝、設定、服務埠還是程式本身。若瀏覽器仍顯示舊畫面，核對服務從哪個工作區啟動；別因連錯版本就叫 agent 重改。若 diff 擴散，先保留目前變更紀錄，再給它具體退件：「保留導覽修正，還原活動與表單修改，重跑 390px 與桌面驗收。」

若 agent 回覆中的測試命令不能在你的機器重跑，先請它補執行位置、版本和必要環境。只有「我已測試」四個字，不能讓你在另一台電腦重現。你可以把這條要求寫進所有任務卡，之後交給合作工程師或客戶的技術團隊時，少一次追問。

一份可複製的指令還要帶著「停止條件」：找不到原預約連結、測試環境缺資料、需要改動付款或真實收件時先停下來。否則 agent 很容易用合理猜測補上商業資料，審查者反而要花時間逐句排除。把停止條件寫在第一輪任務裡，後續退件可以直接引用這個界線。

這份練習的重點，是你能不能在關掉聊天視窗後，仍說得出起點、改了什麼、跑了哪個測試、哪件事還等店主回答。若答案都在交接卡上，第二個工作區才有機會接得順。工作區與分支篇有本案的實際版本畫面；下一篇把三項需求各寫成一張任務卡。
