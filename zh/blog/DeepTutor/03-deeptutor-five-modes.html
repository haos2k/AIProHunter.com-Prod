DeepTutor 五種模式完整解析：Chat、Deep Solve、Quiz、Research、Math Animator

2026 年 4 月 20 日·10 min read

DeepTutor 的介面乍看很簡單——就是一個對話框。但這個對話框裡，有五種完全不同的工作模式。

大多數人第一次進去，用的是最熟悉的那種：Chat，跟 ChatGPT 一樣問問題、等答案。這沒有錯，但只用 Chat，等於買了一台有五個檔位的車，全程掛一檔在開。

這篇把五種模式拆開講清楚——每一種的設計邏輯是什麼、什麼時候切換、怎麼混用效果最好。

模式選擇的基本邏輯

在開始之前，先說一個原則：不同的認知任務，需要不同的 AI 行為。

你在釐清一個概念時，需要的是引導式對話；你在解一道複雜數學題時，需要的是多步驟驗證；你在測試自己是否真的學會了，需要的是出題考你，而不是再解釋一次。

DeepTutor 把這幾種情境的需求，對應到五種不同的模式設計。

模式一：Chat（日常學習對話）

最適合： 概念釐清、快速問答、討論想法、建立學習脈絡

Chat 模式是最基礎的模式，但它不只是「跟 AI 聊天」——結合 DeepTutor 的持久記憶，它的對話品質比一般 AI 聊天工具高出一個層次。

因為 DeepTutor 記住你的程度和目標，Chat 模式的答案會根據你的背景自動校準。同樣的問題，初學者和進階用戶會拿到不一樣深度的回答。

使用技巧：

告訴 DeepTutor 你的對話目標，而不只是提問：

「我剛學完 Transformer 的 Attention 機制，想確認我的理解。
我的理解是：Attention 是在算 Query 和所有 Key 的相似度，
再用這個相似度加權 Value。這樣對嗎？哪裡有盲點？」

這比「解釋 Attention 機制」能帶來更精準的回應。

模式二：Deep Solve（複雜問題多代理解法）

最適合： 有難度的技術問題、需要多步驟推導的題目、需要引用來源的問題

Deep Solve 是 DeepTutor 最「重炮」的模式。它的背後是多代理人協作：問題被拆解成子任務，不同的 agent 分工處理不同面向，最後整合成有完整推理步驟和引用來源的答案。

這和直接問 ChatGPT 的差異，在「驗證步驟」——Deep Solve 在推導過程中會有自我驗證的環節，錯誤率比單一 agent 直接回答低得多。

使用時機：

  • 解一道多步驟的數學或程式設計題目
  • 需要搞清楚一個技術架構的設計決策和依據
  • 問題沒有單一正確答案，需要多角度分析

使用技巧：

給 Deep Solve 足夠的問題背景：

「這是一道 LeetCode Hard：[題目描述]
我的思路是 [你的當前想法]，但在 [某個步驟] 卡住了。
請幫我把整個解題過程拆開，每一步帶推導，最後給 Python 實作。」

Deep Solve 會比 Chat 慢一點——這是正常的，多代理人協作需要時間。

模式三：Quiz（知識測驗與自我評估）

最適合： 測試學習成果、找出盲點、為考試準備、強化記憶

這個模式的設計邏輯來自認知科學裡的 測試效應（Testing Effect）：比起重複閱讀，用測驗的方式複習，記憶留存率高出非常多。

DeepTutor 的 Quiz 不是隨機出題——它會根據你的學習歷史和知識庫內容，出針對你當前程度的題目，並且在你答完後解析你的思維過程，不只告訴你對錯。

使用方式：

「我剛讀完機器學習的 Regularization 章節，
出三題選擇題和兩題簡答題考我，難度中等偏難。
答完後幫我分析哪些概念還需要加強。」

如果你有上傳知識庫，Quiz 也可以針對你的私有文件出題：

「根據我上傳的《系統設計筆記》，
出五題考我 CAP 定理和 Consistency Model 的題目。」

使用技巧：

答完題之後，不要只看對錯——請 DeepTutor 解析你的答題思路：

「我剛才選 B 是因為我以為 [你的理由]，
但正確答案是 C。幫我解釋我的理解為什麼錯了。」

這個「錯在哪裡」的追問，比重新看答案學到更多。

模式四：Research（深度研究，並行代理人）

最適合： 需要整合多個資訊來源、準備報告或論文、了解某個主題的全貌

Deep Research 模式是並行代理人的展現——同時搜尋網頁、學術論文資料庫、和你的本地知識庫，然後整合成有完整引用來源的研究報告。

這不只是「幫你搜尋」，而是幫你做文獻整理：把散落在不同地方的資訊，按照邏輯結構整合起來，每一個主張都帶來源。

使用時機：

  • 「幫我研究 LLM Reasoning 的最新進展，我需要了解主流方向」
  • 「幫我整理 RAG 和 Fine-tuning 的優缺點比較，帶論文引用」
  • 「我在準備一篇關於 [主題] 的文章，幫我做背景研究」

使用技巧：

明確告訴 Research 模式你的輸出格式需求：

「研究主題：Agentic AI 在教育領域的應用現況（2024-2026）
輸出格式：摘要（300 字）+ 主要發現（條列）+ 關鍵論文（帶 DOI）
來源範圍：優先學術論文，補充近期技術部落格。」

給出越清楚的研究框架，輸出的報告就越有用。

模式五：Math Animator（數學概念視覺化）

最適合： 視覺化理解數學或物理概念、製作學習素材、解釋抽象的幾何或微積分概念

Math Animator 是 DeepTutor 最獨特的功能之一——它用 Manim（3Blue1Brown 所用的數學動畫框架）把抽象的數學概念渲染成動畫。

這不是在生成靜態圖表，而是真的有時間軸的動態演示。

最適合的使用場景：

  • 視覺化線性代數概念（矩陣乘法、特徵向量）
  • 微積分的極限和導數直觀理解
  • 概率分布和統計概念的動態演示
  • 任何「用文字說不清楚、需要動態圖才能看懂」的數學

使用方式：

「幫我用動畫演示『傅立葉變換』的直觀概念——
展示一個方波如何被分解成多個頻率的正弦波疊加。」

Math Animator 的生成速度比其他模式慢，但對於某些概念，它的效果是其他任何模式都無法替代的。

五種模式的混用策略

真正的學習，不是線性地用某一種模式到底——而是根據學習狀態流動切換。

一個典型的學習循環長這樣：

Chat（建立概念理解）
  → Deep Solve（用難題驗證理解）
  → Quiz（找出真正的盲點）
  → Chat（針對盲點補充說明）
  → Research（延伸到更大的知識脈絡）

數學主題的流程可能是：

Chat（理解定義）
  → Math Animator（視覺化建立直觀）
  → Deep Solve（解題驗證）
  → Quiz（測試記憶與應用）

不需要每次都走完全部五種，根據你的學習目標選擇對應的入口。

一句話總結

Chat 問、Deep Solve 推導、Quiz 測、Research 整合、Math Animator 看。

五種模式，對應五種不同的認知需求。知道什麼時候切換，你的學習效率可以提高不只一倍。
