CMUX 是什麼？為什麼多 Agent 時代需要它

2026 年 3 月 29 日·4 min read

你有沒有遇過這樣的狀況：三個 AI Agent 同時跑，視窗切來切去，根本不知道哪一格輸出了什麼，通知也不知道從哪冒出來。這不是你不夠專注的問題——是工具設計上根本沒為這個場景想清楚。

CMUX 就是針對這個場景設計的。

CMUX 在解什麼問題

傳統終端機是為「一個人、一個任務、一個視窗」設計的。就算加上 tmux 做視窗管理，結構上還是水平分割、難以識別「哪一格在做什麼任務」。

多 Agent 開發的情境完全不一樣——你可能同時有：

  • 一個代理在幫你寫功能
  • 一個在跑測試
  • 一個在監控 log

這三者如果混在同一個終端機，你等於在用 1990 年的工具管 2026 年的工作流。

CMUX 的解法是：以「工作任務」為單位切分空間，讓每個代理有自己的工作區，你在外面統一看狀態、接通知、下指令。

CMUX 的核心特性

垂直分頁側邊欄：工作區列在左側，不是水平 tab，一眼就能掃完所有工作情境的狀態。

通知面板：代理完成任務或遇到問題，可以主動推送通知，你不用一直盯著每一格輸出。

socket 控制 API：這是最強的一塊。cmux 暴露了 socket API，讓你可以用腳本或外部程式控制終端機——開新工作區、發通知、查詢狀態，全部可以自動化。

內建瀏覽器面板：窗格裡不只能跑終端機，還能開瀏覽器 preview，dev server + 預覽頁面可以放在同一個工作區裡。

和 tmux 有什麼不同

tmux 是通用的終端機多工器，能用但不是專門為 AI Agent 設計的。兩者的差距主要在三點：

介面設計：tmux 的操作邏輯偏指令，CMUX 是原生 macOS 應用程式，有 GUI 設定介面、自動更新、系統通知整合。

瀏覽器支援：tmux 裡你沒辦法開一個真正的 browser panel，CMUX 可以，這對需要即時預覽的工作流差距很明顯。

automation-first 設計：socket API 和 CLI 工具是 CMUX 的一等公民，不是後來才補上的。

適合哪些人用

  • 同時管理 2 個以上 AI Agent 的開發者
  • 使用 Ghostty 或想從 Ghostty 換個更高層工具的人
  • 工作流重複性高、想把「開發環境啟動流程」自動化的人

反過來說：如果你只跑一個代理、任務單純，tmux 或原生 Terminal 其實夠用，不一定要換。

技術底層

CMUX 底層是 Ghostty——一個以效能著稱的終端機引擎。CMUX 把 Ghostty 包起來，加上工作區管理、通知系統、socket API 和內建瀏覽器，讓它從「快速的終端機」變成「AI 代理的控制中心」。

設定檔也繼承自 Ghostty，所以如果你本來就在用 Ghostty，設定幾乎可以直接帶過來。
