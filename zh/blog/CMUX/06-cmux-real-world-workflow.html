多 Agent 實戰工作流：CMUX 在真實開發的使用套路

2026 年 3 月 29 日·5 min read

前面五篇把 CMUX 的每一個功能塊都拆開說了。現在把它們接起來——一個真實開發場景，你同時跑三個 AI Agent，需要各自的空間、能收到完成通知，偶爾還要用腳本控制終端機行為。

場景：三個代理同時跑

假設你今天有三件事要做：

  1. 一個代理在幫你實作新功能（Claude Code / Cursor）
  2. 一個在跑 CI 風格的測試迴圈
  3. 一個在監控 log，確保沒有異常噴出來

這三件事互不相干，但都要跑，而且你希望能一眼看到所有狀態。

工作區設計

按照「工作區 = 任務」的原則，建三個工作區：

工作區名稱 顏色 內容
feature-auth 藍色 代理輸出 + 備用 shell
test-runner 橙色 測試指令輸出
monitoring 灰色 tail -f log 監控

三個工作區各自獨立，側邊欄一眼掃完狀態。

工作節奏建議

早上開工：觸發三個自訂指令，三個工作區全部起來，不用手動配置任何東西。

工作中：代理在跑的時候，你不用一直看它——等通知。通知來了再切過去看結果。

切換情境：側邊欄三個工作區，點一下就切換，不用 ⌘Tab 亂找視窗。

收工前：用 cmux list-workspaces 確認所有工作區狀態，確保沒有代理在跑到一半。

共用機器的注意事項

如果你的開發機是共用的（團隊 server、CI runner），自動化模式建議設「關閉」或「僅限 cmux 程序」，不要開 allowAll——後者讓任何本機程序都能連到你的 CMUX socket，在共用環境裡是個風險。
