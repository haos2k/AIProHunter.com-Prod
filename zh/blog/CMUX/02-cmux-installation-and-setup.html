安裝 CMUX 與 CLI 設定：10 分鐘跑起來

2026 年 3 月 29 日·4 min read

安裝這件事本身不難，但有幾個細節沒搞清楚，之後用 CLI 的時候會卡住。這篇把安裝到驗證的完整流程走一遍，順便說清楚 CLI 設定為什麼要做、什麼時候會用到。

兩種安裝方式

方式一：DMG（推薦）

官網下載 .dmg，打開之後把 CMUX 拖到「應用程式」資料夾——就這樣。後續更新由 CMUX 內建的 Sparkle 自動處理，不需要手動管。

第一次打開 macOS 可能會跳出確認視窗，問你要不要開啟「來自已識別開發者的應用程式」，點打開就好。

這個方式的優點：簡單、自動更新、你只需要下載一次。

驗證安裝是否成功

打開 CMUX，你應該看到：

  • 左側有垂直分頁側邊欄（這是 CMUX 的識別特徵，不是 tmux 那種水平 tab）
  • 一個已經開好的初始工作區
  • 一個準備好接受輸入的終端機

如果看到這三樣東西，安裝就成功了。

CLI 設定：為什麼要做

CMUX 包含一個 cmux CLI 工具，可以讓你在終端機裡直接控制 CMUX——列出工作區、發通知、執行自動化腳本都靠它。

在 CMUX 終端機裡，CLI 自動可用，不需要額外設定。

問題是：如果你在其他終端機（比如 iTerm2、系統 Terminal）裡執行，就找不到 cmux 指令。要解決這個問題，建立一個符號連結就好：

這個設定在以後用自訂指令、CI 整合、自動化腳本的時候會很有用，建議第一次安裝就順手做掉。

自動更新機制

DMG 安裝的用戶不需要擔心手動更新。CMUX 透過 Sparkle 自動檢查更新，有新版本時你會在標題列看到更新提示。也可以手動觸發：選單列 → cmux > 檢查更新。

Homebrew 安裝的用戶就用 brew upgrade --cask cmux 更新。

系統需求快速確認

  • macOS 14.0（Sonoma）或更新版本
  • Apple Silicon 或 Intel Mac 都支援
