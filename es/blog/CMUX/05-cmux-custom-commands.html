Comandos personalizados: haz que CMUX recuerde tu flujo de trabajo

29 3月 2026·4 min read

¿Haces lo mismo cada vez que empiezas a trabajar: abrir un panel para ejecutar npm run dev, cambiar al siguiente para abrir el navegador de preview y luego abrir una shell de reserva? Tres minutos perdidos en configuración manual cada vez.

Los comandos personalizados de CMUX están aquí para resolver ese problema. Define tu entorno de trabajo fijo en cmux.json y, a partir de entonces, un único comando restaura todo el diseño del espacio de trabajo.

Dónde colocar cmux.json

Crea un archivo cmux.json en el directorio raíz de tu proyecto. CMUX lo leerá automáticamente y añadirá los comandos definidos en él a la lista de comandos disponibles.

Dos tipos de comandos

Comando de espacio de trabajo (Workspace Command): abre CMUX y crea un espacio de trabajo con un diseño predefinido, con terminales, navegador y disposición de paneles ya configurados. Ideal para escenarios de «empezar a trabajar».

Comando simple (Simple Command): ejecuta un comando de shell sin crear un espacio de trabajo. Adecuado para operaciones puntuales como «ejecutar pruebas» o «inicializar el entorno».

Desglose de esta configuración:

  • name / description: nombre y descripción que aparecen en la lista de comandos
  • keywords: palabras clave para búsqueda; escribe una palabra y el comando aparece
  • restart: si el espacio de trabajo ya existe, "confirm" pregunta si quieres reiniciarlo; "ignore" lo omite directamente
  • workspace.cwd: directorio de trabajo por defecto para este espacio de trabajo
  • workspace.color: color identificativo de este espacio de trabajo en la barra lateral
  • layout: define la estructura del diseño completo

La lógica de la estructura del diseño: direction es la dirección de la división ("horizontal" para izquierda/derecha, "vertical" para arriba/abajo), split es la proporción de la división (0.5 es mitad y mitad), y children contiene cada panel.

El resultado de este ejemplo es: la mitad izquierda ejecuta Next.js; la mitad derecha tiene la preview del navegador en la parte superior y la shell de reserva en la parte inferior.

Algunos principios de diseño

Piensa bien los keywords: cuando hay muchos comandos, los keywords son la única forma de encontrarlos. Incluye los verbos que sueles escribir, por ejemplo ["start", "dev", "run"].

Usa rutas relativas en cwd: ./web es mejor que /Users/tunombre/projects/app/web. Así la configuración funciona en cualquier máquina sin cambios.

Usa los colores para clasificar: asigna colores distintos a tipos distintos de espacios de trabajo —azul para desarrollo, naranja para pruebas, gris para monitorización. De un vistazo a la barra lateral ya sabes qué es qué.
