Espacios de trabajo, paneles y pestañas: la estructura de tres capas de CMUX al completo

29 3月 2026·5 min read

Mucha gente instala CMUX, lo abre y piensa: «se parece a tmux» —y entonces solo usa el treinta por ciento de sus funcionalidades. El problema suele ser el mismo: no entender su estructura de tres capas. Una vez que la comprendes, cada decisión de diseño cobra sentido y puedes dividir el espacio según las tareas de verdad.

Primero, la vista general

La interfaz de CMUX tiene este aspecto:

┌──────────────────────────────────────────────────────┐
│ ┌──────────────┐ ┌───────────────────────────────────┐ │
│ │ Barra lateral│ │ Espacio de trabajo "dev"          │ │
│ │              │ │                                   │ │
│ │              │ │ ┌───────────────┬───────────────┐ │ │
│ │ > dev        │ │ │ Panel 1       │ Panel 2       │ │ │
│ │   server     │ │ │ [P1] [P2]     │ [P1]          │ │ │
│ │   logs       │ │ │               │               │ │ │
│ │              │ │ │  Terminal     │  Terminal     │ │ │
│ │              │ │ │               │               │ │ │
│ └──────────────┘ └───────────────┴───────────────┘ │ │
└──────────────────────────────────────────────────────┘

A la izquierda está la barra lateral con tres espacios de trabajo (dev, server, logs). El seleccionado actualmente es "dev" y a la derecha se muestran dos paneles en paralelo. Dentro del Panel 1 hay dos pestañas (P1 y P2).

Esto es la estructura de tres capas: espacio de trabajo → panel → pestaña (Surface), más la capa más profunda, la vista (Panel).

Primera capa: ventana (Window)

La capa más exterior es la ventana de macOS, que se crea con ⌘⇧N. En general no necesitas ocuparte de esta capa; las ventanas múltiples solo son útiles cuando tienes suficiente espacio en pantalla.

Segunda capa: espacio de trabajo (Workspace)

El espacio de trabajo es cada elemento de la barra lateral, y se crea con ⌘N.

Esta capa es tu unidad de organización de tareas: un agente, una rama de funcionalidad, una tarea —separa cada cosa en su propio espacio de trabajo. Cada espacio de trabajo tiene su nombre, puede tener un color y dispone de la variable de entorno CMUX_WORKSPACE_ID para que tus scripts sepan en qué espacio de trabajo se están ejecutando.

Ejemplo de uso real:

  • feature-auth: desarrollo de la funcionalidad de autenticación, el agente corre aquí
  • test-runner: espacio de trabajo dedicado a ejecutar pruebas
  • logs: monitorización de logs, se deja correr en segundo plano

Los tres no se interfieren entre sí y puedes ver el estado de todos de un vistazo desde la barra lateral.

Tercera capa: panel (Pane)

Dentro de un espacio de trabajo puedes dividirlo horizontal o verticalmente en varios paneles, usando ⌘D (horizontal) o ⌘⇧D (vertical).

El panel es la unidad de distribución del espacio en pantalla. Te permite ver múltiples salidas dentro de la misma tarea de trabajo. Por ejemplo: a la izquierda corre el servidor de desarrollo y a la derecha la preview del navegador —siguen siendo parte de la misma «tarea», solo que necesitas ver ambas a la vez.

Cuarta capa: pestaña (Surface)

Dentro de cada panel puede haber múltiples Surfaces —como las pestañas de un navegador, que se crean con ⌘T. Cada Surface tiene su propio ID de identificación (CMUX_SURFACE_ID), que se utiliza al hacer automatización con la API de socket.

Vista (Panel)

La capa más profunda. Dentro de cada Surface corre una vista, que puede ser un terminal o un navegador. Sí: puedes abrir el navegador directamente dentro de un panel, sin tener que cambiar a Chrome y volver.

Resumen de las capas

Capa Descripción Cómo crearla Identificación
Ventana Ventana de macOS ⌘⇧N —
Espacio de trabajo Elemento de la barra lateral ⌘N CMUX_WORKSPACE_ID
Panel Región dividida ⌘D / ⌘⇧D ID de panel (API de socket)
Surface Pestaña dentro del panel ⌘T CMUX_SURFACE_ID
Vista Terminal o navegador Automática ID de vista (interno)

Cómo usar esta estructura para gestionar múltiples agentes

Una configuración habitual:

Espacio de trabajo = agente (o tarea)
Un espacio de trabajo por agente, con el nombre de lo que está haciendo: claude-feature, claude-test, monitoring.

Panel = distintos ángulos de observación de la misma tarea
Dentro del espacio de trabajo de una funcionalidad: a la izquierda la salida del agente, a la derecha la preview del navegador. Las dos pertenecen a la misma tarea.

Surface = espacio de reserva
Una Surface de shell de reserva dentro de un panel, lista para ejecutar cosas manualmente en cualquier momento sin interferir con la salida principal del agente.

Con este diseño tu pantalla no se desordena: cada panel tiene su rol y sabes exactamente dónde mirar.
