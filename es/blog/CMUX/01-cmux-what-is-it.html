¿Qué es CMUX? Por qué lo necesitas en la era de los múltiples agentes

29 3月 2026·4 min read

¿Te ha pasado alguna vez? Tres agentes de IA corriendo a la vez, cambiando de ventana sin parar, sin saber qué salida pertenece a qué panel, y las notificaciones apareciendo de no se sabe dónde. No es que te falte concentración —el problema es que las herramientas no se diseñaron pensando en este escenario.

CMUX existe precisamente para eso.

Qué problema resuelve CMUX

Los terminales tradicionales se diseñaron para «una persona, una tarea, una ventana». Aunque tmux añade gestión de ventanas, la estructura sigue siendo una división horizontal donde es difícil identificar «qué tarea está haciendo cada panel».

El desarrollo con múltiples agentes es un contexto completamente diferente. Es posible que tengas al mismo tiempo:

  • Un agente escribiendo código de una funcionalidad
  • Otro ejecutando pruebas
  • Otro monitorizando logs

Si los tres conviven en el mismo terminal, estás usando herramientas de 1990 para gestionar un flujo de trabajo de 2026.

La solución de CMUX es: dividir el espacio por unidad de tarea de trabajo, de modo que cada agente tenga su propio espacio de trabajo y tú puedas ver el estado global, recibir notificaciones y dar órdenes desde fuera.

Características principales de CMUX

Barra lateral con pestañas verticales: los espacios de trabajo aparecen en la parte izquierda, no como pestañas horizontales. De un vistazo puedes ver el estado de todos los contextos de trabajo.

Panel de notificaciones: cuando un agente completa una tarea o encuentra un problema, puede enviarte una notificación activa, sin que tengas que estar mirando la salida de cada panel constantemente.

API de control por socket: es la parte más potente. cmux expone una API de socket que te permite controlar el terminal mediante scripts o programas externos —abrir nuevos espacios de trabajo, enviar notificaciones, consultar el estado— todo automatizable.

Panel de navegador integrado: dentro de los paneles no solo puedes correr un terminal, también puedes abrir una vista previa del navegador. El servidor de desarrollo y la página de preview pueden coexistir en el mismo espacio de trabajo.

En qué se diferencia de tmux

tmux es un multiplexor de terminal de propósito general: funciona, pero no fue diseñado específicamente para agentes de IA. Las diferencias principales son tres:

Diseño de interfaz: tmux opera con una lógica orientada a comandos; CMUX es una aplicación nativa de macOS con interfaz gráfica de configuración, actualizaciones automáticas e integración con las notificaciones del sistema.

Soporte de navegador: dentro de tmux no puedes abrir un panel de navegador real; CMUX sí permite hacerlo, y la diferencia es notable en flujos de trabajo que requieren previsualización en tiempo real.

Diseño automation-first: la API de socket y las herramientas de CLI son ciudadanos de primera clase en CMUX, no fueron añadidas a posteriori.

Para quién es adecuado

  • Desarrolladores que gestionan 2 o más agentes de IA simultáneamente
  • Usuarios de Ghostty o personas que buscan una herramienta de nivel superior a Ghostty
  • Quienes tienen flujos de trabajo muy repetitivos y quieren automatizar el proceso de arranque del entorno de desarrollo

Dicho esto: si solo corres un agente y tus tareas son sencillas, tmux o el Terminal nativo son suficientes. No es necesario cambiar.

Base técnica

CMUX está construido sobre Ghostty, un motor de terminal conocido por su rendimiento. CMUX envuelve Ghostty y le añade gestión de espacios de trabajo, sistema de notificaciones, API de socket y un navegador integrado, transformándolo de «un terminal rápido» en «un centro de control para agentes de IA».

El archivo de configuración también se hereda de Ghostty, así que si ya lo usabas, la configuración puede trasladarse casi directamente.
