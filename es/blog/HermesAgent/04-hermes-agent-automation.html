Automatización con Hermes Agent: Programación Cron, Sub-Agentes Paralelos y Ejecución de Código

19 4月 2026·7 min read

El patrón de uso de la mayoría de las herramientas de IA es: tú preguntas, responde, y eso es todo.

Este patrón tiene una restricción dura: tienes que estar presente. Si no preguntas, nada ocurre. Querer que la IA haga cosas cuando no estás, o ejecutar varias líneas de tareas paralelas simultáneamente, generalmente requiere una solución compleja.

Hermes Agent rompe directamente esta restricción. Este artículo cubre tres capacidades centrales de automatización: programación Cron, sub-agentes paralelos (Delegación) y Ejecución de Código.

Programación Cron: Deja que las Tareas se Ejecuten Solas a las 3am

Configúralo y olvídate. Cada mañana a las 8am desde ese momento, Hermes se despierta y ejecuta la tarea — sin necesidad de estar presente, sin sesión abierta, sin nada que escribir.

Las Tareas Cron Pueden Llevar Skills

Hay una integración crítica aquí: las tareas Cron pueden adjuntarse a una skill para su ejecución.

Esto eleva a Cron de "programar la ejecución de un prompt" a "programar la ejecución de un flujo de trabajo completo" — la lógica de pasos de la skill, los problemas conocidos y los métodos de verificación se incluyen en el viaje.

Delegación: Asignar un Trabajo a Tres Sub-Agentes Simultáneamente

La herramienta delegate_task permite al agente poner en marcha hasta 3 sub-agentes, cada uno ejecutando una tarea independiente — con su propio contexto, su propio toolset, su propia sesión de terminal.

El caso de uso más directo: necesitar investigar múltiples temas en paralelo.

Tres sub-agentes buscan simultáneamente, el agente principal espera a que todos terminen y luego agrega — el tiempo total es "el tiempo del sub-agente más lento", no "la suma de los tres."

Características de los Sub-Agentes

  • Contexto aislado: Los sub-agentes no conocen el contenido de la conversación principal, solo la tarea que se les ha asignado
  • Toolset restringido: Puedes especificar qué herramientas puede usar un sub-agente (p.ej. solo búsqueda web, sin terminal)
  • Sesión de terminal independiente: Los comandos del sub-agente no afectan el directorio de trabajo del agente principal

Este diseño de aislamiento importa — puedes con seguridad dejar que los sub-agentes ejecuten operaciones con efectos secundarios (como desplegar a staging para pruebas) sin preocuparte de que arruinen el entorno principal.

Cuándo Usar la Delegación

Bueno para:

  • Tareas de investigación paralelas independientes (buscar tres temas diferentes simultáneamente)
  • Operaciones de entorno aisladas (uno prueba el enfoque A, otro prueba el enfoque B)
  • Sub-tareas claramente delimitadas (dejar que el sub-agente escriba el frontend, tú manejas el backend)

No es bueno para:

  • Tareas con fuertes dependencias secuenciales (A debe completarse antes de que B pueda empezar)
  • Tareas que requieren estado compartido pesado (la comunicación entre sub-agentes es costosa)
  • Tareas secuenciales simples (la Delegación en realidad sería más lenta)

Ejecución de Código: Comprimir Flujos de Trabajo de Múltiples Pasos en un Solo Turno de LLM

Esta es la parte más técnica de las capacidades de automatización de Hermes, pero también donde las ganancias de eficiencia son más significativas.

Las llamadas a herramientas normales funcionan así: cada llamada a herramienta es un turno de LLM — el agente llama a la herramienta A, espera los resultados, lee los resultados, decide el siguiente paso, llama a la herramienta B, espera los resultados, continúa.

execute_code permite al agente escribir un script Python que llama a múltiples herramientas de Hermes en secuencia — todo el flujo de trabajo de múltiples pasos comprimido en un solo turno de LLM.

Desde la perspectiva del LLM, esta es una llamada a herramienta — pero lo que realmente se ejecuta son tres búsquedas más una escritura de archivo.

Casos de Uso

  • Procesamiento de datos en lote: Procesar cien URLs, archivos o puntos de datos de una vez
  • Automatización condicional: "Si los resultados de búsqueda tienen menos de 3 artículos, intentar diferentes palabras clave y buscar de nuevo"
  • Encadenamiento de múltiples herramientas: Buscar → analizar → formatear → guardar, todo en uno

Cómo Trabajan Juntas las Tres Capacidades

Estas tres herramientas están diseñadas para complementarse, no para sustituirse:

Capacidad Qué Problema Resuelve Mejor Para
Cron Tareas que se ejecutan cuando no estás Resúmenes diarios, monitoreo de salud, limpieza periódica
Delegación Ejecutar múltiples líneas de tareas paralelas simultáneamente Investigación paralela, pruebas de despliegue A/B
Ejecución de Código Compresión de eficiencia para flujos de trabajo de múltiples pasos Procesamiento en lote, pipelines de datos complejos

Una combinación típica:

Cada mañana a las 8am (Cron) → poner en marcha tres sub-agentes (Delegación) → cada uno busca un tema separado (Ejecución de Código para procesamiento en lote) → el agente principal agrega → envía a Telegram.

Configúralo una vez, se genera automáticamente cada día después de eso.

La Brecha con Otras Herramientas

La mayoría de las herramientas de IA no tienen integración nativa de estas tres cosas — para lograr efectos similares, normalmente necesitarías combinar API de IA + cron jobs + tu propio código de unión en Python, con costos de mantenimiento no triviales.

Hermes hace que todas sean funciones nativas, y las integra con el sistema de Skills y el sistema de memoria — las tareas programadas pueden llevar skills, los sub-agentes pueden usar el conocimiento de fondo inyectado por la memoria del agente principal, y la Ejecución de Código puede llamar a cualquier herramienta de Hermes.

Ese nivel de integración es donde las capacidades de automatización entregan valor real.
