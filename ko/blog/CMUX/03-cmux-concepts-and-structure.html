워크스페이스, 패널, 탭: CMUX 3단계 구조 완전 해설

2026년 3월 29일·7 min read

많은 사람이 CMUX를 설치한 후 열어보고는 "tmux랑 비슷하네"라고 생각하고는 기능의 30%만 사용합니다. 문제는 대개 3단계 구조를 제대로 파악하지 않았기 때문입니다. 이해하고 나면 각 설계 결정이 왜 의미 있는지 알게 되고, 진짜로 작업 단위로 공간을 분리할 수 있습니다.

먼저 전체 모습 보기

CMUX의 인터페이스는 이렇게 생겼습니다:

┌──────────────────────────────────────────────────────┐
│ ┌──────────┐ ┌─────────────────────────────────────┐ │
│ │ Sidebar  │ │ Workspace "dev"                     │ │
│ │          │ │                                     │ │
│ │          │ │ ┌───────────────┬─────────────────┐ │ │
│ │ > dev    │ │ │ Pane 1        │ Pane 2          │ │ │
│ │   server │ │ │ [S1] [S2]     │ [S1]            │ │ │
│ │   logs   │ │ │               │                 │ │ │
│ │          │ │ │  Terminal     │  Terminal       │ │ │
│ │          │ │ │               │                 │ │ │
│ └──────────┘ └───────────────┴─────────────────┘ │ │
└──────────────────────────────────────────────────────┘

왼쪽은 사이드바로 세 개의 워크스페이스(dev, server, logs)가 나열되어 있습니다. 현재 "dev"가 선택되어 있고, 오른쪽에 두 개의 나란한 패널이 표시되며, 패널 1 안에는 두 개의 탭(S1과 S2)이 있습니다.

이것이 세 단계입니다: 워크스페이스 → 패널 → 탭(Surface), 그리고 최하단의 패널(Panel).

1단계: 창(Window)

가장 바깥쪽은 macOS 창으로, ⌘⇧N으로 새로 만듭니다. 일반적으로 이 단계를 신경 쓸 필요는 없습니다. 다중 창은 모니터 공간이 충분할 때 사용하는 시나리오입니다.

2단계: 워크스페이스(Workspace)

워크스페이스는 사이드바의 각 항목으로, ⌘N으로 만듭니다.

이 단계가 작업을 구성하는 단위입니다—에이전트 하나, 기능 브랜치 하나, 작업 하나를 워크스페이스 하나로 분리합니다. 각 워크스페이스는 자체 이름과 색상을 설정할 수 있으며, 환경 변수 CMUX_WORKSPACE_ID를 통해 스크립트가 어느 워크스페이스에서 실행 중인지 알 수 있습니다.

실제 사용 시나리오:

  • feature-auth: Auth 기능 개발, 이 에이전트가 여기서 실행
  • test-runner: 테스트 전용 워크스페이스
  • logs: 로그 모니터링, 스크롤하며 방치

세 가지가 서로 간섭하지 않으며, 사이드바에서 한눈에 상태를 스캔할 수 있습니다.

3단계: 패널(Pane)

워크스페이스 안에서 가로 또는 세로로 분할해 여러 패널을 만들 수 있습니다. ⌘D(수평) 또는 ⌘⇧D(수직)로 분할합니다.

패널은 화면 공간을 배분하는 단위로, 같은 작업 내에서 여러 출력을 동시에 볼 수 있게 합니다. 예를 들어 왼쪽에서 dev 서버를 실행하고, 오른쪽에서 브라우저 미리보기를 열 수 있으며, 둘 다 같은 '작업'에 속하지만 동시에 볼 필요가 있습니다.

4단계: 탭(Surface)

각 패널 안에 여러 Surface를 가질 수 있습니다. 브라우저의 탭과 유사하며, ⌘T로 추가합니다. 각 Surface는 자체 식별 ID(CMUX_SURFACE_ID)를 가지며, 소켓 API로 자동화할 때 사용됩니다.

패널(Panel)

최하단입니다. 각 Surface 안에서 패널이 실행되며, 패널은 터미널 또는 브라우저가 될 수 있습니다. 그렇습니다, 패널 안에서 직접 브라우저를 열 수 있어 Chrome으로 전환했다가 돌아올 필요가 없습니다.

계층 구조 개요

계층 설명 생성 방법 식별 방법
창 macOS 창 ⌘⇧N —
워크스페이스 사이드바 항목 ⌘N CMUX_WORKSPACE_ID
패널 분할 영역 ⌘D / ⌘⇧D 패널 ID (소켓 API)
Surface 패널 내 탭 ⌘T CMUX_SURFACE_ID
패널 터미널 또는 브라우저 자동 패널 ID (내부)

이 구조로 여러 에이전트를 관리하는 방법

일반적인 구성:

워크스페이스 = 에이전트 (또는 작업)
각 에이전트에게 워크스페이스 하나, 이름은 무엇을 하는지로—claude-feature, claude-test, monitoring.

패널 = 같은 작업 내의 다른 관찰 각도
같은 feature 워크스페이스에서, 왼쪽은 에이전트 출력, 오른쪽은 브라우저 미리보기. 둘 다 같은 작업에 속합니다.

Surface = 예비 공간
패널 하나에 shell Surface를 미리 만들어두면, 언제든지 전환해 수동으로 무언가를 실행할 수 있으며 주 에이전트의 출력을 방해하지 않습니다.

이렇게 설계하면 화면이 어지럽지 않습니다. 각 칸에 역할이 있고, 어디를 봐야 할지도 알 수 있습니다.

3단계 구조를 파악했다면, 다음 편에서 설정을 조정합니다—폰트, 색상, 스크롤 등 편안하게 사용하기 위한 세부 사항: CMUX 설정 파일 완전 가이드.

CMUX는 Ghostty 기반의 경량 macOS 네이티브 터미널로, 여러 AI 에이전트 관리를 위해 설계되었습니다. 이 글에서는 어떤 문제를 해결하는지, tmux와 어떻게 다른지, 누구에게 적합한지 명확하게 설명합니다.
