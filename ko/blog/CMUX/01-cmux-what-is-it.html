CMUX란 무엇인가? 다중 에이전트 시대에 왜 필요한가

2026년 3월 29일·6 min read

이런 상황을 겪어본 적 있나요? AI 에이전트 세 개를 동시에 실행하면서 창을 이리저리 전환하다 보면, 어느 패널에서 무슨 출력이 나왔는지 알 수가 없고, 알림도 어디서 나타나는지 모릅니다. 이것은 집중력이 부족한 문제가 아닙니다. 도구 설계 자체가 이 시나리오를 전혀 고려하지 않은 겁니다.

CMUX는 바로 이 시나리오를 위해 설계되었습니다.

CMUX가 해결하는 문제

기존 터미널은 '한 사람, 한 작업, 한 창'을 위해 설계되었습니다. tmux로 창 관리를 추가해도, 구조적으로는 수평 분할이고 '어느 패널이 어떤 작업을 하는지' 식별하기 어렵습니다.

다중 에이전트 개발 환경은 완전히 다릅니다. 동시에 이런 상황이 펼쳐질 수 있습니다:

  • 에이전트 하나는 기능을 구현 중
  • 하나는 테스트를 실행 중
  • 하나는 로그를 모니터링 중

이 세 가지가 하나의 터미널에 뒤섞이면, 1990년대 도구로 2026년의 워크플로를 관리하는 셈입니다.

CMUX의 해결책은: '작업 단위'로 공간을 분리해 각 에이전트에게 전용 워크스페이스를 주고, 바깥에서 상태를 통합 확인하고, 알림을 받고, 명령을 내릴 수 있게 하는 것입니다.

CMUX의 핵심 기능

수직 탭 사이드바: 워크스페이스가 왼쪽에 나열되며, 수평 탭이 아닙니다. 한눈에 모든 작업 상황의 상태를 스캔할 수 있습니다.

알림 패널: 에이전트가 작업을 완료하거나 문제가 발생하면 알림을 능동적으로 푸시합니다. 각 패널 출력을 계속 주시할 필요가 없습니다.

소켓 제어 API: 가장 강력한 기능입니다. cmux는 소켓 API를 노출해 스크립트나 외부 프로그램으로 터미널을 제어할 수 있습니다. 새 워크스페이스 열기, 알림 전송, 상태 조회 등 모두 자동화할 수 있습니다.

내장 브라우저 패널: 패널에서 터미널만 실행하는 게 아니라 브라우저 미리보기도 열 수 있습니다. dev 서버와 미리보기 페이지를 같은 워크스페이스에 둘 수 있습니다.

tmux와 어떻게 다른가

tmux는 범용 터미널 멀티플렉서로, 사용할 수 있지만 AI 에이전트를 위해 특별히 설계된 것은 아닙니다. 두 가지의 차이는 주로 세 가지입니다:

인터페이스 설계: tmux의 조작 방식은 명령어 중심이고, CMUX는 macOS 네이티브 앱으로 GUI 설정 인터페이스, 자동 업데이트, 시스템 알림 통합을 갖추고 있습니다.

브라우저 지원: tmux에서는 진짜 브라우저 패널을 열 수 없지만, CMUX는 가능합니다. 실시간 미리보기가 필요한 워크플로에서 차이가 확연합니다.

자동화 우선 설계: 소켓 API와 CLI 도구는 CMUX의 1등 시민으로, 나중에 추가된 기능이 아닙니다.

누구에게 적합한가

  • AI 에이전트 2개 이상을 동시에 관리하는 개발자
  • Ghostty를 사용 중이거나 Ghostty에서 더 상위 레이어 도구로 전환하고 싶은 분
  • 워크플로 반복성이 높고 '개발 환경 시작 프로세스'를 자동화하고 싶은 분

반대로 말하면: 에이전트를 하나만 실행하고 작업이 단순하다면, tmux나 기본 Terminal로도 충분하며 반드시 전환할 필요는 없습니다.

기술적 기반

CMUX의 기반은 Ghostty입니다. 성능으로 유명한 터미널 엔진이죠. CMUX는 Ghostty를 감싸 워크스페이스 관리, 알림 시스템, 소켓 API, 내장 브라우저를 추가해 '빠른 터미널'에서 'AI 에이전트의 제어 센터'로 만들었습니다.

설정 파일도 Ghostty에서 상속받으므로, 기존에 Ghostty를 사용 중이라면 설정을 거의 그대로 가져올 수 있습니다.
