커스텀 명령어: CMUX가 내 워크플로를 기억하게 하기

2026년 3월 29일·7 min read

매번 작업을 시작할 때 같은 일을 반복하고 있지 않나요? 패널 하나를 열어 npm run dev를 실행하고, 전환해서 preview 브라우저를 열고, shell을 하나 더 열어 대기시켜 두는 것 말입니다. 매번 수동으로 설정하다 보면 3분이 그냥 사라집니다.

CMUX의 커스텀 명령어는 바로 이 문제를 해결하기 위한 것입니다. 고정된 작업 환경을 cmux.json으로 작성해두면, 이후 명령어 하나로 전체 워크스페이스 레이아웃을 복원할 수 있습니다.

cmux.json 위치

프로젝트 루트 디렉토리에 cmux.json을 만들면, CMUX가 자동으로 읽어 안에 정의된 명령어를 사용 가능 목록에 추가합니다.

두 가지 명령어 유형

워크스페이스 명령어(Workspace Command): CMUX를 열고 미리 설정된 레이아웃의 워크스페이스를 만듭니다. 터미널, 브라우저, 분할 방식이 모두 정의되어 있습니다. '작업 시작' 같은 시나리오에 적합합니다.

간단한 명령어(Simple Command): 셸 명령어를 실행하며, 워크스페이스를 만들지 않습니다. '테스트 실행', '환경 초기화' 같은 일회성 작업에 적합합니다.

워크스페이스 명령어: 개발 환경 정의

가장 완전한 예시로, 명령어 하나로 Next.js dev 서버 + 브라우저 미리보기 + 대기 shell을 동시에 엽니다:

이 설정 해설:

  • name / description: 명령어 목록에 표시되는 이름과 설명
  • keywords: 검색용으로, 키워드를 입력하면 이 명령어를 찾을 수 있습니다
  • restart: 워크스페이스가 이미 존재할 경우, "confirm"은 재시작 여부를 묻고, "ignore"는 건너뜁니다
  • workspace.cwd: 이 워크스페이스의 기본 작업 디렉토리
  • workspace.color: 사이드바에서 이 워크스페이스의 식별 색상
  • layout: 전체 레이아웃 구조 정의

레이아웃 구조 논리: direction은 분할 방향("horizontal" 좌우, "vertical" 상하), split은 분할 비율(0.5는 반반), children에 각 패널을 배치합니다.

이 예시로 만들어지는 결과: 왼쪽 절반에서 Next.js 실행, 오른쪽 절반 상단은 브라우저 미리보기, 하단은 대기 shell.

간단한 명령어: 일회성 작업

레이아웃이 필요 없는 작업에는 간단한 형식을 사용합니다:

confirm: true는 실행 전 확인 창을 띄웁니다. 파괴적인 작업(캐시 초기화, 의존성 재설치)에 적합합니다.

로그 모니터링 워크스페이스

또 다른 일반적인 시나리오—로그 전용 워크스페이스를 열어 스크롤하며 방치:

restart: "ignore"의 논리: 이 워크스페이스가 이미 실행 중이면 재시작하지 않고 계속 모니터링하게 합니다.

몇 가지 설계 원칙

keywords는 신중하게 정하세요: 명령어가 많아지면 keywords만이 찾는 방법입니다. 자주 입력하는 동사를 넣으세요. 예: ["start", "dev", "run"].

cwd에는 상대 경로 사용: ./web이 /Users/yourname/projects/app/web보다 좋습니다. 설정을 다른 기기에서도 바로 사용할 수 있습니다.

색상으로 분류하세요: 워크스페이스 유형별로 다른 색상—개발은 파란색, 테스트는 주황색, 모니터링은 회색. 사이드바를 한눈에 스캔해서 구분할 수 있습니다.

커스텀 명령어를 설정했다면, 마지막 편에서 이 모든 것을 실제 다중 에이전트 워크플로로 조합하는 방법을 살펴봅니다: 다중 에이전트 실전 워크플로: CMUX를 실제 개발에 활용하는 방법.

다중 에이전트 실전 워크플로: CMUX를 실제 개발에 활용하는 방법

앞에서 배운 것을 모두 연결합니다: 여러 AI 에이전트를 동시에 관리하는 방법, 소켓 API로 알림을 자동화하는 방법, 서로 간섭하지 않는 다중 에이전트 작업 환경을 설계하는 방법.

CMUX 입문 과정: 터미널을 제대로 써야 AI 에이전트 관리가 엉키지 않는다

CMUX를 처음 접하는 개발자를 위한 시리즈 개요. CMUX가 어떤 문제를 해결하는지, 어떻게 배우는지, 그리고 권장 학습 순서를 빠르게 파악할 수 있습니다.

CMUX 설정 파일 완전 가이드: 폰트, 색상, 스크롤과 분할 패널

CMUX는 Ghostty 설정 파일 형식을 상속합니다. 이 글에서는 외관, 동작, 분할 패널, 브라우저 동작을 모두 하나씩 설명하며, 바로 사용할 수 있는 완전한 설정 예시도 포함합니다.

워크스페이스, 패널, 탭: CMUX 3단계 구조 완전 해설

CMUX의 핵심은 워크스페이스(Workspace), 패널(Pane), 탭(Surface) 3단계 구조입니다. 이 세 단계를 이해해야 AI 에이전트를 어떻게 배분하고, 작업 상황을 전환하고, CMUX의 시각적 인터페이스가 무엇을 말하는지 알 수 있습니다.
