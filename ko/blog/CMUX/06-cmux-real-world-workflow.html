다중 에이전트 실전 워크플로: CMUX를 실제 개발에 활용하는 방법

2026년 3월 29일·7 min read

앞의 다섯 편에서 CMUX의 각 기능 블록을 하나씩 설명했습니다. 이제 연결해봅니다—실제 개발 시나리오에서 세 개의 AI 에이전트를 동시에 실행하며, 각자의 공간이 필요하고, 완료 알림을 받을 수 있어야 하고, 때로는 스크립트로 터미널 동작을 제어해야 하는 상황입니다.

시나리오: 에이전트 세 개 동시 실행

오늘 해야 할 세 가지가 있다고 가정합니다:

  1. 에이전트 하나가 새 기능을 구현 중 (Claude Code / Cursor)
  2. 하나가 CI 스타일의 테스트 루프를 실행 중
  3. 하나가 로그를 모니터링하며 이상 출력이 없는지 확인 중

이 세 가지는 서로 관련이 없지만 모두 실행해야 하며, 전체 상태를 한눈에 볼 수 있어야 합니다.

워크스페이스 설계

'워크스페이스 = 작업' 원칙에 따라 세 개의 워크스페이스를 만듭니다:

워크스페이스 이름 색상 내용
feature-auth 파란색 에이전트 출력 + 대기 shell
test-runner 주황색 테스트 명령어 출력
monitoring 회색 tail -f 로그 모니터링

세 워크스페이스가 각자 독립적이며, 사이드바에서 한눈에 상태를 스캔할 수 있습니다.

cmux.json 설계

이 세 워크스페이스를 모두 커스텀 명령어로 작성해두면, 아침에 작업을 시작할 때 하나씩 실행해 세 환경을 모두 일으킬 수 있습니다:

CLI로 알림 전송

에이전트가 큰 작업을 완료했을 때, 계속 출력을 지켜보는 대신 알림을 받고 싶다면 스크립트나 에이전트 설정에 추가하세요:

CMUX 외부에서 이 명령어를 호출할 경우(예: CI 스크립트), 먼저 /usr/local/bin/cmux 심볼릭 링크를 만들어야 합니다(설치 편 참조).

소켓 API 자동화: 고급 사용법

소켓 API를 사용하면 프로그램으로 CMUX를 제어할 수 있습니다. 사용 전, '자동화 모드' 설정을 확인하세요:

설정 > 자동화 모드 > cmux 프로세스만 (개인 개발 기기에 권장)

모든 워크스페이스 조회:

이 명령어의 반환 정보를 스크립트에 연결해 '특정 워크스페이스가 존재하는지 확인하고, 없으면 자동으로 만드는' 로직을 구현할 수 있습니다.

작업 리듬 제안

아침 시작 시: 세 개의 커스텀 명령어를 실행해 세 워크스페이스를 모두 일으킵니다. 수동으로 설정할 필요가 없습니다.

작업 중: 에이전트가 실행되는 동안 계속 지켜볼 필요가 없습니다—알림을 기다리세요. 알림이 오면 전환해서 결과를 확인합니다.

상황 전환: 사이드바의 세 워크스페이스를 클릭 한 번으로 전환. ⌘Tab으로 창을 찾아 헤맬 필요가 없습니다.

퇴근 전: cmux list-workspaces로 모든 워크스페이스 상태를 확인해 작업 중인 에이전트가 없는지 확인합니다.

공유 기기 주의사항

개발 기기가 공유 환경(팀 서버, CI 러너)이라면, 자동화 모드는 '끄기' 또는 'cmux 프로세스만'으로 설정하고, allowAll을 사용하지 마세요. 후자는 모든 로컬 프로세스가 CMUX 소켓에 연결할 수 있게 하므로, 공유 환경에서는 위험합니다.

여기까지 CMUX의 완전한 워크플로가 연결되었습니다. 설치, 구조, 설정, 커스텀 명령어, 그리고 다중 에이전트 실전까지—에이전트를 몇 개 실행하든 엉키지 않는 반복 가능한 방법론입니다.

CMUX 입문 과정: 터미널을 제대로 써야 AI 에이전트 관리가 엉키지 않는다

CMUX를 처음 접하는 개발자를 위한 시리즈 개요. CMUX가 어떤 문제를 해결하는지, 어떻게 배우는지, 그리고 권장 학습 순서를 빠르게 파악할 수 있습니다.

CMUX란 무엇인가? 다중 에이전트 시대에 왜 필요한가

CMUX는 Ghostty 기반의 경량 macOS 네이티브 터미널로, 여러 AI 에이전트 관리를 위해 설계되었습니다. 이 글에서는 어떤 문제를 해결하는지, tmux와 어떻게 다른지, 누구에게 적합한지 명확하게 설명합니다.

CMUX 설정 파일 완전 가이드: 폰트, 색상, 스크롤과 분할 패널

CMUX는 Ghostty 설정 파일 형식을 상속합니다. 이 글에서는 외관, 동작, 분할 패널, 브라우저 동작을 모두 하나씩 설명하며, 바로 사용할 수 있는 완전한 설정 예시도 포함합니다.

워크스페이스, 패널, 탭: CMUX 3단계 구조 완전 해설

CMUX의 핵심은 워크스페이스(Workspace), 패널(Pane), 탭(Surface) 3단계 구조입니다. 이 세 단계를 이해해야 AI 에이전트를 어떻게 배분하고, 작업 상황을 전환하고, CMUX의 시각적 인터페이스가 무엇을 말하는지 알 수 있습니다.
