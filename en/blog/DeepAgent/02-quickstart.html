After that, every invoke or stream automatically sends a trace to the LangSmith dashboard. Highly recommended to keep this enabled during debugging — everything the agent does becomes immediately visible.

Common First-Time Pitfalls

Don't skip the tool docstring: The agent uses a tool's docstring to decide when to call it. The more clearly you write it, the more accurately the agent will make decisions. An empty or unclear docstring will cause the agent to pick the wrong tool or not call it at all.

Get the system_prompt right: Not too short, not too long. The key is clearly describing the agent's role and main tasks — something like "You are a research assistant skilled at X, Y, Z" is far more useful than "You are an AI assistant."

invoke input format: Use the messages key, with a list as the value, where each message has role and content. This format is fixed — getting it wrong will give you a direct error, not some weird output.

What You Have Now

An agent that can:

  • Call custom tools
  • Stream intermediate steps
  • Be traced through LangSmith

But this agent is still missing one capability — planning. Hand it a complex task and it will start doing things, but it won't break the task down and sequence it first. That's what the next article addresses.
