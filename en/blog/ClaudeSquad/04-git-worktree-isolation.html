Git Worktree Isolation: The Key to Keeping Multiple Agents from Interfering with Each Other in Claude Squad

May 14, 2026·4 min read

You have two agents working at the same time — one adding a new feature, one fixing a bug. If they're both modifying the same working directory with the same codebase, what happens?

Best case: git conflicts you have to resolve manually. Worst case: one agent's changes directly overwrite the other's and you don't even know it happened.

Claude Squad solves this with git worktree. This article explains how it works.

What Is Git Worktree

Normally your git repo has one working directory — you work in ~/projects/my-app, and when you checkout a branch, the files in that folder change to match that branch's content.

git worktree is a lesser-known git feature that lets you check out different branches in multiple directories simultaneously. Each directory is a real working directory with its own branch, and changes don't affect each other.

How Claude Squad Uses Worktrees

Every time you create a new session in Claude Squad, it does several things in the background:

  1. Creates a new branch from your current branch (name is auto-generated with a timestamp)
  2. Creates a git worktree on that new branch, placed alongside the main working directory
  3. Starts a tmux session in that worktree directory
  4. Runs your configured AI agent inside the tmux session

All of the agent's operations — reading files, modifying code, creating new files — happen inside that isolated worktree directory. It cannot see or touch the working directories of other sessions.

What It Actually Looks Like

Suppose your repo is at ~/projects/my-app and you create two Claude Squad sessions:

~/projects/
├── my-app/                    ← Your main working directory (main branch)
├── my-app--claude-squad-1/    ← Session 1's worktree (cs/task-abc123 branch)
└── my-app--claude-squad-2/    ← Session 2's worktree (cs/task-def456 branch)

Each claude-squad-N directory is a complete, usable working directory — you can cd into it and all files are there. Running git log shows the commit history for that branch.

Worktrees Are Cleaned Up When Sessions Are Deleted

When you press D to delete a session in the Claude Squad TUI, Claude Squad will:

  1. Terminate the tmux session
  2. Remove the corresponding git worktree
  3. Remove that branch from the worktree list

Why This Design Is Better Than "Opening Multiple Terminals"

Opening multiple terminals means multiple agents sharing the same working directory — any time agent A and agent B modify the same file, that's a conflict. There's no way to let two agents "simultaneously" work safely on the same codebase.

The worktree design makes "working simultaneously" truly safe: each agent has its own branch, its own working directory, its own commit history. What you do at the end is code review and merge, not conflict resolution.

This isn't just an efficiency question — it's the fundamental difference between whether parallel work is actually possible.
