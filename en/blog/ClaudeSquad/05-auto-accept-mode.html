Claude Squad Auto-Accept Mode: Let Agents Run Quietly While You Work on Something Else

May 16, 2026·4 min read

When letting an agent run a task, there's one annoying thing — it hits a confirmation prompt partway through and stops to wait for your answer:

Are you sure you want to delete this file? (y/n)
Do you want to continue? (y/n)

If you're right there, fine — press y and keep going. But if your intention was to let the agent run in the background while you do other things, these interruptions are painful. You have to keep watching, or come back to find it waiting there having done nothing.

Auto-accept mode is designed for exactly this.

How to Enable Auto-Accept

Launch Claude Squad with the -y flag:

With this enabled, all sessions managed by this cs process will automatically accept agents' confirmation prompts without stopping to wait for you.

Alternatively, if you only want specific sessions to run in auto-accept mode, you can specify this when creating the session — this lets different tasks have different levels of automation.

What This Mode Does

The -y flag tells Claude Squad to automatically respond to interactive prompts the agent encounters in the background.

For Claude Code, this is equivalent to its "yolo mode" — the agent doesn't need to pause for your confirmation and continues executing directly. For tools like Aider, the effect is similar, automatically confirming places that require human input.

The result is: you start a task, walk away to do other things, and the agent quietly runs to completion without needing you nearby.

When to Enable Auto-Accept

Tasks suitable for auto-accept:

  • The task description is very specific and clearly scoped — you know exactly what the agent will change
  • Low-risk tasks: writing documentation, writing tests, adding comments, formatting code
  • You've run similar tasks before and roughly know how the agent behaves
  • The task runs in an isolated worktree, so even if something goes wrong, you'll review before merging

Working contexts suitable for auto-accept:

  • You have multiple tasks to run in parallel and can't babysit each one
  • The task is expected to run for a while (over 10 minutes) and you want to do other things
  • This is a "let it run, I'll review the diff later" workflow

When Not to Enable Auto-Accept

Tasks to avoid:

  • Vague task descriptions with unclear scope — the agent might go in directions you didn't expect
  • Tasks that operate on databases, external APIs, or production environments
  • High-risk refactoring — the agent is changing many places and you need to confirm at key decision points

Contexts to avoid:

  • You're trying this type of task for the first time and aren't sure how the agent will behave
  • The results would be hard to reverse (e.g., batch file deletion)

To put it plainly, auto-accept is a "I'm confident about this task" mode — not a "I can't be bothered to watch" mode. Every time the agent automatically bypasses a confirmation, you're silently accepting that decision.

When the agents finish, come back and press tab to switch to diff mode for each session to review their changes, then push once you confirm everything looks good.

Best Practices for Background Execution

Auto-accept mode lets agents run without interruption, but you still need to do code review — the timing just shifts from "confirm mid-task" to "review afterward."

A few habits that make this workflow safer:

Make task descriptions specific enough: "Write tests for this" is ten times safer than "optimize the code" — the former has a clear scope, the latter could mean anything.

Use the diff view: After an agent finishes, press tab in the Claude Squad TUI to check the diff, confirm the changes are within expected range before merging.

Start with small tasks: The first time you use auto-accept, choose a small, limited-impact task — get a feel for how the agent behaves in this mode, then gradually expand usage.
