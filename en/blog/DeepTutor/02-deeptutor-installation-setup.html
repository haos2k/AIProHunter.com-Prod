Initial Setup: First Time in the Interface

Once installed, there are a few things worth configuring before you start learning.

1. Build your learning profile

On first login, DeepTutor will walk you through your basic learning preferences:

  • Learning goals: What do you want to learn? (e.g., "Master Python data analysis," "Reach IELTS 7.0")
  • Current level: Self-assess as beginner / intermediate / advanced
  • Learning style preference: Direct explanation vs. guided questioning (Socratic)

This information is stored in DeepTutor's persistent memory and influences the tone of all future interactions. The more detail you provide, the less recalibration you'll need later.

2. Choose your LLM model

You can adjust the model in the settings interface. Recommendations:

  • Daily chat and quizzes: gpt-4o-mini or claude-3-5-haiku (fast, cost-effective)
  • Deep Solve and Deep Research: gpt-4o or claude-3-5-sonnet (higher accuracy)
  • Privacy-first: llama3.2 (fully local, but lower performance)

3. Create your first Knowledge Base (optional)

If you have learning materials on hand, you can set up a knowledge base at this stage. Upload PDFs or Markdown files—DeepTutor will build semantic indexes in the background, typically completing within a few minutes.

Detailed Knowledge Base usage is covered in Article 5 of this series.

Troubleshooting Common Issues

Q: Docker started but localhost:3000 won't open

Check whether the containers are running:

If backend or frontend status isn't Up, check the logs:

The most common cause is an incorrect or empty API key in .env.

Q: Uploaded a PDF but nothing happens

Knowledge base indexing is asynchronous—large files may take a few minutes. If it's still not complete after ten minutes, trigger re-indexing from the settings page.

Q: Using Ollama but conversation is very slow

Confirm Ollama is running on the correct port and that OLLAMA_BASE_URL is set correctly. On macOS with Apple Silicon, ensure Ollama is using Metal acceleration.

Q: Permission errors with Docker on Windows

Make sure Docker Desktop has WSL 2 backend enabled, and that your working directory is under C:\Users\ rather than another drive.
